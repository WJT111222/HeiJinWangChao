# 三阶段工作流 · 精简版 · 给 Codex

设计稿：`heijin-workflow.html`，基于主界面 v5。
- **查看方式：**
  - 点输入台上方的「详情」展开。
  - 也可以用链接：`#flow=ready&wf=1`、`#flow=error&wf=1&foot=diag`、`#flow=off&wf=1`、`#flow=busy&wf=1`、`#flow=settled&wf=1`。
- 「设计稿控制 → 回合状态」可以切换 6 种状态，只用于演示，**不要实现**。

## 范围
- **只改 `GameScreen.tsx` 里 `section.workflow` 的结构和样式。**
- **不变的部分：**
  - TurnCoordinator、自动执行、各阶段生成、取消、结算、错误处理、运行开关
  - 所有显示条件，以及 `workflowLabel` 等状态计算
- **文案：** 全部沿用现有文案。新增的只有主操作按钮旁的一行说明，见第二节。
- **保留：** `role="status"`、`aria-live`、`role="alert"`、`aria-controls="workflow-runtime-switches"`、`data-testid="summary-length"`。
- **嵌套组件：** `VariableCandidates`、`WorldCandidates`、`RuntimeLogPanel`、`StageResponsesPanel`、`RequestUsage`、`StoryInspectionPanel` 原样放进新位置，只调整外层样式。

## 问题与思路
现在展开「详情」后，从上到下依次堆着：提示、主按钮、5 种错误、费用提示、三个阶段（每个阶段下面带按钮和完整候选）、诊断、已绑定输入、运行开关。内容会把输入台推得很高，信息没有主次。

精简后：
- **收起时**：只有一条进度轨（与主界面 v5 一致）。
- **展开时**：在输入台上方弹出一张浮层卡片，**不推动布局**，内部分四层：
  1. 状态标题
  2. 需要处理的事（错误或提示，与主操作放在一起）
  3. 三张阶段卡
  4. 次要信息折叠在底栏

## 一、收起态（进度轨）
- 结构与主界面 v5 一致，依次为：「三阶段 · {workflowLabel}」、三段进度条、「详情」按钮。
- 「详情」按钮：
  - 改为 `aria-expanded` 和 `aria-controls` 指向浮层，右侧加一个小三角，展开时朝上。
  - 状态为 error 时，按钮用赭红色描边。
- 每段进度条下面的文字：已完成的阶段显示「已完成」，回合结算后显示「已结算」，其余沿用现有的阶段状态文案。

## 二、展开态（浮层 `.wf-pop`）
- **位置与尺寸**
  - `position: absolute`，以输入台为定位基准，`bottom: 100%`；左右边距与阅读区对齐。
  - 最大高度 `min(62vh, 560px)`，超出部分在卡片内滚动。
- **外观**：背景 `#0f1211`，完全不透明，避免正文透出来；12px 圆角，上方带深色阴影。
- **入场动画**：从下方 8px 处淡入，0.22s；reduced-motion 下关闭。
- **关闭方式**：右上角 ×、Esc、再点一次「详情」。关闭后焦点回到「详情」按钮。
- 原来的 `<details>` 改成受控的展开状态。`openRuntimeSettings()` 需要改成：先展开浮层，再聚焦对应的开关。

**1）头部**：状态圆点，加上 `workflowLabel`（加粗）。圆点颜色：
- 生成中：金色，并闪烁
- 失败：赭红
- 已结算或候选已完成：绿色
- 阶段关闭：金色

**2）提示区**（有内容时才显示）
- 错误：把 `automatic.error / error / submitError / variables.error / world.error` 合并成一个 `role="alert"` 区块。
  - 赭红边框，浅红底色；第一行是错误文本，第二行用小字写失败码和重试次数（如果有）。
  - 右侧放「打开 AI 设置」按钮（只在原来就有这个按钮的场景下显示）。
- 阶段提示 `workflowGuidance`：`role="note"`，金色边框；右侧是「展开高级设置」，点击后聚焦并高亮对应的阶段开关。
- 草稿无效的提示也放在这个区块里，用 note 样式。

**3）主操作行**
- 只在原有条件下显示主按钮：完成本回合结算 / 继续未完成阶段 / 自动生成本回合 / 自动生成开局 / 取消自动执行。
- 主按钮使用金色 `.primary`；「取消自动执行」用描边按钮。
- 按钮右侧加一行小字说明（**新增文案**）：

  | 状态 | 说明 |
  |---|---|
  | 可结算 | 三个阶段的候选均已通过校验 |
  | 自动执行中 | 正在依次执行三个阶段 |
  | 其他 | 从第一个未完成的阶段继续 |

**4）三张阶段卡**（`.wf-stages`，三列；1199px 及以下为一列）
- 外层 `ol` 的 id 改为 `workflow-runtime-switches`，`runtimeSwitches` 的 ref 也挂在这里。
- 每张卡片：
  - 顶部依次是：序号 0N、阶段名、状态胶囊（文案沿用现有的阶段状态计算）。
  - 卡片顶边有 2px 色条：已完成为金色，生成中为亮金，失败为赭红并且卡片边框也变成赭红，已关闭的卡片整体降低透明度。
- **正文卡**：只放原来的提示「正文生成与重新 Roll 位于行动输入旁。」
- **变量卡 / 世界卡**
  - 头部下方放一个「启用」小开关，就是原来的运行开关：变量管理 / 动态世界。它从原来的底部开关区移到这里，逻辑不变，`title` 写明对应的阶段。
  - 操作按钮沿用原文案和禁用条件：生成或重新生成候选、启用并补算、取消生成。
  - 后面接原来的 `VariableCandidates` / `WorldCandidates` 组件入口按钮「查看变量候选（未结算）/ 查看世界候选（未结算）」，样式改为蓝色文字链接，点击后仍然打开原来的候选弹窗。弹窗样式见 `FEEDBACK_HANDOFF.md`。

**5）底栏**
- 「重试与变更详情」「本回合已绑定输入（只读）」做成两个文字开关，原来是两个独立的 `<details>`，现在一次只展开一个，内容显示在底栏下方。
- 「生成可能产生第三方 API 费用。」移到底栏右侧，用小字。
- 诊断区里的内容（摘要字数、失败码、运行日志、阶段响应、请求用量、正文检查）原样保留，统一用小号文字。

## 验收要点
1. 以下 6 种状态下，进度轨、浮层头部、提示区、主操作、阶段卡显示都正确：已结算、生成中、某阶段失败、候选完成待结算、阶段关闭、开局等待。
2. 浮层不会把输入台和正文推开；在 1440×900 和 1280×800 下不溢出；内容多时在卡片内滚动。
3. 「展开高级设置」能打开浮层，并聚焦到第一个未开启的阶段开关。
4. 键盘：Tab 顺序合理，Esc 关闭后焦点回到「详情」。读屏能听到状态变化和错误。
5. 现有 e2e 只调整选择器，不改断言含义。要特别检查依赖 `details.workflow-disclosure` 展开的测试。
