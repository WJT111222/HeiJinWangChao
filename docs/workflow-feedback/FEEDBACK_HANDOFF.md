# 提示与弹窗规范 · 给 Codex

设计稿：`heijin-feedback.html`，一张规范页，按 01–06 分节。

## 范围
- **只改样式和容器结构。** 显示条件、文案、`role`、`aria-label` 都不变。
- **不在本次范围：**
  - 创角（`CreationWizard`）和开局包（`OpeningPacks`）的报错，留到创角系统一起做。
  - 游戏菜单弹窗（仅 ≤900px 出现），随移动端一起做。
- **新增 CSS 变量**，分深色（主界面、首页）和档案纸（档案柜、设置）两套，档案纸那套写在 `.archive` 作用域里：

| 级别 | 用途 | role | 深色 文字 / 底 / 边 | 档案纸 主色 |
|---|---|---|---|---|
| 错误 `err` | 失败，需要用户处理 | alert | `#D47C60` / `#c26a4a16` / `#6e4a3d` | `#A3412E` |
| 注意 `warn` | 未保存、阶段关闭、草稿过期、「待确认」 | note | `#E0C27A` / `#c9a96112` / `#5a5034` | `#8E6C25` |
| 说明 `info` | 费用提醒、规则、进行中 | status | `#8EC1E0` / `#8ec1e012` / `#34505f` | `#2D5E7D` |
| 完成 `ok` | 保存成功、测试成功 | status | `#7DBB9C` / `#7dbb9c12` / `#35574a` | `#2F7A58` |

## 一、嵌入式提示框 `.alert.l-{err|warn|info|ok}`
**结构**（从左到右）
1. 圆形级别标记：1.35rem，单字依次为「误 / 注 / 示 / 成」，`aria-hidden`。
2. 文字：
   - 第一行是结论，用级别色、加粗。
   - 第二行是小字补充，写原因、失败码或后果。
   - 拆行规则：原文案含句号或分号的，在第一个句号或分号处拆开，不改任何字；只有一句的就只显示一行。
3. 右侧按钮：只放原来就有的按钮（如「打开 AI 设置」「取消请求」），不新增。
4. 可关闭的提示在最右放 ×。

**适用位置**
- `.story-error`、`.field-hint`（提示类）、`.workflow-fee`
- `TurnUndoControl` 里的 `role="alert"`
- `AiConnections` 的 `.notice`
- 设置页底部的 `role="status"` 提示
- 删除存档弹窗里的 `deleteError`

**`.alert` 只换外层容器，`role` 跟原来一致。**

## 二、全局提示条（原 `.app-error`）
- **位置：** `position: fixed`，顶栏下方 1rem，水平居中，宽 `min(40rem, 100vw - 2rem)`。不推动布局，层级高于档案柜面板。
- **外观：**
  - 背景 `#151917`，1px 级别色边框，左侧一条 3px 内阴影色条，外加投影。
  - 内容依次是：圆形级别标记、文案、×（`aria-label="关闭提示"` 不变）。
- **动画：** 从上方 8px 处淡入，0.3s；reduced-motion 下关闭。
- **逻辑：** 不变。只有错误级，同一时间只显示一条，不自动消失。
- **首页：** 没有顶栏，提示条贴在视口顶部 1rem 处。

## 三、小确认弹窗（`Dialog small`）
所有小弹窗统一使用这套样式：
- 撤回上一回合
- 记忆总结失败 / 待确认
- AI 配置尚未保存
- 删除存档（首页已设计，结构对齐这里）

**结构**
- **顶部：** 一条 3px 级别色条。
  - 撤回：注意级
  - 总结失败：错误级
  - 总结「待确认」：注意级
  - 未保存：注意级
  - 删除：错误级
- **头部：** 2.1rem 单字方印，方印字为弹窗主题字（撤 / 忆 / 存 / 删，新增装饰，`aria-hidden`）；标题用衬线；右侧是 ×。
- **正文：** 左边缘和标题文字对齐。
  - 后果说明用小圆点列表。比如撤回弹窗原来的三条 `<p>`（已撤回的剧情无法重做……、当前未结算草稿会被丢弃、输入框现有文字会被本次回填替换）改成 `<ul>`，显示条件不变。
  - 补充说明用灰色小字。
  - 弹窗内的报错用 `.alert`。
- **底栏：** 浅一级底色，按钮右对齐。
  - 危险确认用赭红实心按钮，如「确认撤回」「确认删除」。
  - 主操作用金色，如「重新生成」「前往设置选择人物」。
  - 次要操作用描边或幽灵按钮，如「保留当前回合」「暂停自动总结」「取消」。
- **档案纸版（设置内）：**
  - 弹窗底色 `#EFE8D9`，底栏底色 `#E8E0CF`。
  - 主操作用墨色实心按钮 `.btn-ink`，危险操作用朱砂描边。
  - 现在设置里的「AI 配置尚未保存」：主操作「继续编辑」用墨色实心，「放弃本次修改」用朱砂描边，位置在右侧。
- 原来按钮的禁用条件和执行中文案（「正在撤回…」「正在删除…」）不变。

## 四、候选查看弹窗（`VariableCandidates` / `WorldCandidates` 的 Dialog）
- **入口：** 工作流阶段卡里的「查看变量候选（未结算）/ 查看世界候选（未结算）」。
- **尺寸：** 宽 `min(56rem, 94vw)`，深色。
- **头部：**
  - eyebrow「STAGE 02 · VARIABLES」或「STAGE 03 · WORLD」（新增装饰）。
  - 标题沿用原文。
  - 状态胶囊：
    - 变量候选：「未正式结算」，金色。
    - 世界候选：「程序校验通过 · 仍未正式结算」为绿色，「预览 · 变量依赖未完成，不能正式结算」为金色。
- **主体：** 两栏。
  - **左栏 15rem：**
    - 版本号：正文版本、执行版本、候选版本，等宽字。
    - 三张计数卡：合法命令（绿）、拒绝建议（赭红）、未解决事项（金）。数据取自原来那句「合法命令 N 条；拒绝建议 N 条；未解决事项 N 条。」，改成卡片展示，含义不变。
    - 「主动查看 / 隐藏完整变量候选」开关（`StageResponseText`），做成蓝色文字链接。
  - **右栏：**
    - 「程序编译和校验后的候选」或「程序校验后的候选」作为分节标题。
    - 命令列表每行依次是：类型标签（等宽蓝色）、说明、命令 ID（等宽灰色）。拒绝项用赭红标签，未解决项和「缺失」项用金色标签。
    - 原始响应展开后放进深色等宽代码框，最高 9rem，超出部分滚动。
- 弹窗里的字段和条件渲染全部保持原样，只换容器和排版。

## 五、三阶段工作流内的报错
已在 `WORKFLOW_HANDOFF.md` 中定义：错误合并为一个 `.alert.l-err`，阶段提示用 `.alert.l-warn`，草稿无效也用 `.alert.l-warn`。颜色和结构以本规范为准。

## 验收要点
1. 每个报错和确认位置都能触发，并按本规范显示：
   - 全局报错条：存档读取失败、列表失败、最近选择保存失败、运行偏好保存失败
   - 撤回：确认，以及两种失败
   - 记忆总结：失败、待确认、缺少目标人物
   - 设置里 AI 连接的各类提示
   - 两种候选弹窗
2. 读屏朗读和现在一致（`role` 不变）；弹窗焦点陷阱和关闭后焦点返回的行为不变。
3. 深色和档案纸两种底色上，文字对比度都达到 WCAG AA。
4. 现有 e2e 只调整选择器，不改断言含义。
