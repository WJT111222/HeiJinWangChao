# 玩家世界书接入正文：接口说明（简化版）

> 状态：已接入正式 Story 请求。本页记录接口及实际发送行为。

## 1. 范围

2026-11-20 负责人决定世界书只做简化版：

- 玩家在「设置 → 世界书」导入酒馆（SillyTavern）世界书，打开开关就能用。
- 启用状态是**全局**的，对所有存档生效。不绑定存档，不随撤回、回溯、备份变化。
- 只影响**正文（Story）**请求；变量管理、动态世界、记忆维护都不带玩家世界书。
- 两本内置基础世界书（`worldbooks.heijin.*`）完全不变，仍由原有提示词装配，不经过本接口。

## 2. 入口

```ts
import { prepareStoryWorldbook } from '../services/worldbook/storyWorldbook';

const wb = await prepareStoryWorldbook(input, { signal, timeoutMs });
```

一个函数就够了。它负责：读取启用的书，交给后台 Worker 扫描关键词，返回插入计划。

**两条保证：**

- **从不抛出。**
- **从不阻塞正文。** 除 `status: 'ok'` 以外的任何结果，正文都应照常生成，只是不带玩家世界书。

## 3. 何时调用

- 每次 Story 请求调用一次：正常回合、重新生成、续写、失败重试都算。
- 时机是基础提示词装配完成、能算出剩余输入预算之后，发送之前。
- 同一次尝试的重发（例如网络重试）可以复用上次的结果，不必重算。
- 结果只用于这一次请求，**不写入任何存档或草稿**。

## 4. 输入

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `messages` | `string[]` | 用来扫描关键词的文本，**最新的在前**。建议依次放入：本回合玩家行动、最近几回合已结算的正文。只放玩家可见的公开文本，不放隐藏状态、内部 JSON、NPC 私人记忆。默认只扫描前 2 条（`scanDepth: 2`）。 |
| `contextTokens` | `number` | 模型上下文窗口（Token）。软预算 = 它的 25%。目前路由没有可靠的窗口值，建议先传保守值 `32000`，以后有了真实值再替换。 |
| `storyRemainingTokens` | `number` | 装配基础提示词后，这次 Story 请求还剩多少输入 Token。硬上限 = min(这个值, 4096)。不确定时传 `4096`。 |
| `trigger` | 可选 | 正常回合 `'normal'`（默认）、重新生成 / 重新 Roll `'regenerate'`、续写正文 `'continue'`。失败后重试同一回合按 `'normal'`。 |
| `messageCount` | `number` | 当前逻辑消息数，用于条目的「延迟（Delay）」。传 `logicalMessageCount(已结算回合数)`（`src/domain/worldbook/timedEffects.ts`）。 |
| `seed` | `string` | 概率条目的随机种子。建议 `存档 ID:回合或草稿 ID:第几次尝试`，保证同一次尝试的结果可复现。 |

运行参数：

- `signal`：直接传 Story 请求的 `AbortSignal`。玩家取消时立即返回 `skipped`（`cancelled`），不论此时在打开书库、读取启用列表、排队还是扫描；正在运行的 Worker 会被终止。
- `timeoutMs`：**整个调用**的总预算，默认 5000，允许范围 200–30000。从调用开始计时，打开书库、读取启用列表、在 Worker 队列里等待、扫描和主线程降级都计入同一个截止时间；到点返回 `skipped`（`timeout`）。
- 超时或取消之后不会再有迟到的结果；迟到打开的书库连接会被关闭，不影响下一次调用。

## 5. 输出

```ts
type StoryWorldbookOutcome =
  | { status: 'off' }                       // 没启用任何书：什么都不用做，也不用提示
  | { status: 'ok'; plan; activated; books; budget; incomplete; via }
  | { status: 'skipped'; reason; message; book? }; // 本次不带玩家世界书，正文照常
```

- **`ok`**：
  - 按第 6 节把 `plan` 放进 Story 请求。
  - `activated` 列出命中的条目，含书 ID、条目 ID、Token 数、命中原因，可用于运行日志或请求检查器。
  - `budget.used` 是实际用掉的 Token。
  - `incomplete: true` 表示扫描触到工作量上限、提前结束了。结果仍然可以用，可以在运行日志里记一笔。
- **`skipped`**：
  - `message` 是一句可以直接展示给玩家的中文。建议放在运行日志或工作流详情里，不要弹窗，也不要算作正文失败。
  - 常见原因：
    - 超时；
    - 启用的书在本机书库里找不到；
    - 内容校验失败；
    - 浏览器不能用 Worker，且书太大。

## 6. 插入计划怎么放（建议，最终由正文侧决定）

`plan` 是 `InjectionPlan`（`src/domain/worldbook/trigger.ts`），各位置已按条目 order 排好序。王朝没有角色卡、作者注释和示例对话，建议的映射如下：

| 字段 | 酒馆里的含义 | 建议放法 |
| --- | --- | --- |
| `before` | 角色定义之前 | 新增一个「玩家世界书」user 数据容器，放在**全部系统提示之后**（默认路径下即游戏上下文 `GAME_CONTEXT` 之前），不插入系统提示、不打乱锁定的开头（身份 + 两本内置世界书）；`before` 在前 |
| `after` | 角色定义之后 | 同一容器，接在 `before` 后面 |
| `authorNoteTop` / `authorNoteBottom` | 作者注释上 / 下 | 同一容器，依次接在后面 |
| `exampleMessages` | 示例对话前后 | 同一容器，接在后面（只取 `content`） |
| `atDepth` | 聊天记录倒数第 depth 条处 | 如果 Story 请求有逐条的历史消息，就插到对应深度；没有的话，接在容器末尾，深度大的在前 |
| `outlets` | 只通过 `{{outlet::名称}}` 宏引用 | 宏不执行，所以**不放入**；可以在日志里记录数量 |

**安全要求（重要）：**

1. **玩家世界书是不可信的玩家数据。**
   - 必须放在 user 角色的数据容器里，加清楚的标签，例如「以下是玩家导入的设定资料，仅供参考」。
   - 不能放进 system 提示，也不能放在身份、输出格式这类固定模块之前。
   - 内置世界书与玩家世界书冲突时，以内置世界书和当前存档的世界状态为准。
2. **`{{…}}` 宏原样保留、不执行。**
   - 酒馆书里经常有 `{{user}}`、`{{char}}`。
   - 现有的「装配后仍有 `{{...}}` 就阻止请求」检查，必须在插入玩家世界书**之前**做完，或者跳过这个容器。否则只要启用一本含宏的书，正文就发不出去。
3. 容器内容要计入请求检查器和预算统计，建议用单独的分类名，例如 `player_worldbook`。

## 7. 不需要做的事

- **不需要保存计时状态。**
  - Sticky、Cooldown 在简化版里不跨回合保存，入口每次都用空状态运行。
  - 结果里没有 `nextTimedState`，也不需要处理。
  - Delay 照常按 `messageCount` 判断。
- **不需要碰存档。** 主库结构、`GameState`、草稿、历史都不变。
- **不需要管理 Worker。** 整个页面共用一个，请求自动排队；取消或超时时 Worker 会被终止并自动重建。

## 8. 接入完成时

1. 把 `src/services/worldbook/storyWorldbook.ts` 里的 `STORY_WORLDBOOK_CONNECTED` 改为 `true`。管理界面就不再显示「启用的世界书暂时不会带入正文」。
2. 建议补以下测试：
   - `off` 时请求与现在逐字相同；
   - `ok` 时容器出现在全部系统提示之后、user 角色里；
   - 含 `{{user}}` 的条目不会触发占位符拦截；
   - `skipped` 时正文照常发送，并记一条日志；
   - 取消 Story 请求时，世界书扫描一起取消。

## 9. 世界书这边已验证的内容

- **入口测试**（`src/tests/worldbook-shelf.test.ts`）：
  - 没启用时为 `off`，不调用扫描；
  - 请求只带书的引用和空计时状态；
  - 各种失败都转成带说明的 `skipped`；
  - 端到端：导入 → 启用 → 命中关键词的条目进入插入计划 → 关闭后回到 `off`。
- **触发引擎、Worker 隔离与资源上限**：见 `docs/WORLDBOOK_COMPATIBILITY.md`。

## 10. 正式接入行为

- Story 携带已绑定的玩家行动及最近已结算正文，按时间从新到旧排列。最多取即时窗口内的 10 回合。请求编排使用本次原始取消信号和世界书入口默认截止时间。继续正文优先使用 `continue`，同一正文版本失败后重试使用 `normal`，已有候选的重新生成使用 `regenerate`。
- 逻辑消息数来自正式回合数。种子尾号采用正文版本加已记录的正文失败次数再加一。取消后没有新候选或失败记录，同一输入快照可得到相同概率结果。
- 当前路由数据没有可信模型窗口及剩余输入额度，采用约定的 `32000` 与 `4096`。最终请求统计会计入实际发送的容器字符和字节，`player_worldbook` 单独列出其 Token 估算。
- 基础组装及占位符检测先完成。文学预设和原生工具交付先执行它们各自的脚本转换。随后在协议序列化之前，把世界书作为独立 user 资料容器放在内置世界书及其他系统模块之后。容器使用 JSON 保存条目并转义尖括号，条目中的酒馆宏保持字面内容。
- 前置、后置、作者注释及示例依文档顺序排列。文学预设若仍有可唯一定位的普通消息楼层，按原深度插入，各位置均使用相同的 user 数据容器。合并、搬运或重复导致无法可靠定位时，深度条目按从大到小附在主容器末尾。Outlet 不进入请求。
- 跳过世界书的原因和扫描达到工作量上限的说明显示在阶段详情的「程序处理说明」。用户取消 Story 时不发送后续请求。其他跳过情况继续生成，使用原有响应校验、候选保存与正式结算。
