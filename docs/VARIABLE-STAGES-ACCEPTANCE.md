# 第一阶段工程验收

基线为 `release/1.0` 的 `f6ca1ca8e961652ea8cdb8a490e3e8d653cd0482`。模拟测试覆盖流程，真实模型验收由负责人在取得供应商凭证后执行。

## 对定稿的兼容性修正

人物阶段可以先保存结构校验后的实体候选，供主角与现场阶段引用。接触归属、结构和已有依据可以验证的引用在第一遍检查。现场阶段提供合法结束时钟后，再按原领域规则检验互动与记忆时间。关闭现场阶段时沿用已有合法时钟。结算重新验证同一份候选。

RecordHistory 归场外与网络阶段。有效历史视角和现场已经形成的结案候选会加载纪事目录与规则。普通回合即使没有排期，原事件规则也允许场外阶段同批新建并终结事件，因此该阶段保留归档能力。沿用同批 SaveEvent、RecordHistory 及最终投影校验，由模型判断重大性。结构化归档与本回合一次提交。普通史料和双视角纪事继续可用。

场外任务继承原有离场规则。SaveTask 可以用已离场的接触者作执行人，均以候选投影的在场状态和既有开局同伴保护为准。人物档案、记忆及受保护家庭字段继续使用整回合接触名单。

## 固定存档与预算

使用 Node 24，分别为两个检出目录安装锁文件依赖。以下命令从 PR 工作目录执行。

```sh
git worktree add --detach ../heijin-baseline f6ca1ca8e961652ea8cdb8a490e3e8d653cd0482
npm ci --prefix ../heijin-baseline
npm ci
node scripts/measure-variable-prompts.mjs ../heijin-baseline
npm run prompts:budget
```

脚本按正式装配器及阶段选择器构造普通用餐、现场结案、回顾往事三组请求。专属字符统计包括阶段模板、变量组、输出协议、命令目录和最终格式提醒。整段另含共同背景、上下文及存档。字数以 Unicode 码点计，估算 Token 使用项目内估算器。CI 对每组每段执行 60,000 专属字符上限，三段差异超过 20% 时提示。

| 普通用餐回合 | 专属字符 | 专属估算 Token | 全请求字符 | 全请求估算 Token |
| --- | ---: | ---: | ---: | ---: |
| 基线 Variables | 93,682 | 41,441 | 114,010 | 62,725 |
| 基线 World | 70,149 | 38,725 | 91,650 | 60,600 |
| 人物与实体 | 40,879 | 17,810 | 61,141 | 39,078 |
| 主角与现场 | 48,399 | 19,771 | 68,672 | 41,042 |
| 场外与网络 | 59,953 | 29,932 | 81,525 | 51,825 |

三个场景在各自版本中得到相同的专属字数。普通回合的下游全请求总估算由 123,325 增至 131,945，分段会重复发送共同背景。三段最大值比最小值高约 46.5%，触发均衡提示。

## 真实模型成对对照（待执行）

先用固定回包验证两套执行路径与输入指纹。脚本从指定检出目录加载实际提示词、模型适配器、解析器、候选验证和结算。默认使用模拟传输，可离线执行。

```sh
node scripts/compare-variable-models.mjs ../heijin-baseline --mock > /tmp/heijin-before-mock.json
node scripts/compare-variable-models.mjs . --mock > /tmp/heijin-after-mock.json
```

对照使用同一正式存档、同一篇已选正文和同一玩家行动。源文件为 `scripts/variable-comparison-fixture.mjs`。普通样本从 08:00 开始，现金为 100 元，正文明确经过十分钟并付现金 30 元。预期结束时钟为 08:10，现金为 70 元，消费只记一次。重复运行的 `identicalInput` 应完全相同。

负责人将获准的 OpenAI 兼容端点、固定版本模型和临时凭证分别绑定到 `HEIJIN_COMPARE_ENDPOINT`、`HEIJIN_COMPARE_MODEL`、`HEIJIN_COMPARE_KEY`。关闭流式，temperature 固定为 0，每次输出上限 8,192 Token。两个检出目录均运行工作分支中同一份驱动脚本。每次从原始输入重新开始，交替执行两臂并至少各重复三次，保留失败运行。记录两个提交 SHA 和供应商模型版本。

```sh
node scripts/compare-variable-models.mjs ../heijin-baseline --live > /tmp/heijin-before-1.json
node scripts/compare-variable-models.mjs . --live > /tmp/heijin-after-1.json
```

| 指标 | 核对方法 |
| --- | --- |
| 命令遗漏 | 逐次对照正文的明确变化，记录缺少的时钟或消费及对应阶段。 |
| 错填或重复 | 校对账户、金额及单位、时间、实体引用和额外写入；逐条列出差异。 |
| 校验失败 | 同时检查运行失败码、候选 settlement 内跳过的更新、最终结算结果。分别报告失败回合数及失败命令数。 |
| Token | 按阶段记录供应商 usage，并加总输入及输出。供应商缺报时填写缺报。 |
| 耗时 | 报告各阶段及整轮耗时、各臂中位数和范围，保留失败样本。 |

负责人对照正文做离线评分。评分不进入游戏运行链路。提交验收表时附输入指纹、配置、各阶段候选和统计，不附凭证。独立复审、真实模型验收及 #247 正式合流后的专项回归分别记录。
