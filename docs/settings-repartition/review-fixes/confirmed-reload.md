# AI 设置部分回滚后的确认重读

上轮复审基线为 `47cf3103ad23a2b7ac4eff6bb59e09981f207d87`。本次仅调整 AI 设置保存出错后的恢复流程。

| 保存结果 | 玩家看到的状态 | 下一步 |
| --- | --- | --- |
| 事务中止，配置、两处密钥及同步标记均已恢复并核验 | 草稿保留，保存按钮可用 | 排除故障后直接重试 |
| 回滚不完整、所有权已变化或恢复状态无法核验 | 显示故障原因和「重新读取最新配置」，保留草稿，停用旧草稿的编辑和保存 | 可以取消并保留草稿，也可以确认用最新配置和密钥替换草稿 |
| 确认后重读仍失败 | 草稿和保存限制继续保留 | 排除存储故障后再次重读 |
| 确认后重读成功 | 渠道与模型分配共用最新的编辑基准，保存按钮等待新的修改 | 玩家重新编辑并正常保存 |

已删除按配置值回推失败残留以及按本次残留密钥调整旧基准的代码。确认重读复用已有标签间互斥和同步标记，在同一受保护的读取中取得渠道、模型路由、持久及会话密钥。当两处标记一致时，重读只读取存储。已识别的中止事务如果留下未对齐的标记，只修复该同步元数据。此操作不写入业务配置和密钥。正常保存继续使用原字段合并与冲突判定。
