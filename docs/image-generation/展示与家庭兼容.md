## 居家照与已有存档

`home` 是现有人物图片用途的新增枚举值。所属游戏存档、人物类型、稳定人物 ID、已有身份键及用途共同确定当前选图。每次上传或生成写入独立资源 ID。同一人物的 `avatar`、`bust`、`full` 和 `home` 分别维护历史与选用状态。家庭字段不会接收图片数据。居家照沿用人物锚点，直接生成和词组转化都有日常居家构图提示。已有自定义转换模板在读取时保留，旧配置会补齐居家照模板。

图库仍使用 IndexedDB V8 和备份 V3。已有图片资源 ID、用途值与字节内容无需迁移。新版读取旧图库，带图备份可恢复居家照、历史版本和当前选择，轻量备份保留本机同身份图库。升级前的旧客户端缺少 `home` 枚举，包含该用途的备份应使用新版恢复。图库分类分别提供车辆和物品，居家照可单独筛选，也可在人物分类中查找。

## 家庭系统与历史时间线

#219 的头提交为 `d7ea348f05520c5c121671931cbd19d1b1baabe8`。本次核对时 #219 仍是面向 main 的草稿；#248 使用的 release/1.0 基线已包含相同的家庭面板及家庭领域目录。家庭面板在两处的 Git blob 均为 `a98fd374e746cdf755fa758d7f8cdff87f49af22`。本次直接接入基线已有的现役成员判定和成员详情。Chromium 用例通过正式家庭领域命令退出成员、调整在任地位，再经备份覆盖与刷新确认退出记录、家庭展示和图库导出。此次接入仅存在于 #248 功能分支；合流时应继续保留现役成员 ID 校验。

历史插画按正式 turnId 关联。生成时优先使用该回合在当前撤回链中的同期存档，提取相关人物最小外貌资料、游戏日期和场景；找不到可靠快照时，取当时的正文、摘要及已记录的场景。之后修改的年龄、外貌、锚点不会补入旧剧情。回溯、撤回、删除及覆盖已有存档后，打开的页面重新核对存档实例和当前回合，失效图片仍归图库管理。查看、选择、导出、加入或退出家庭均不发起模型调用。手动居家照生成走已有付费队列；自动任务拒绝该用途。

## 长存档资源管理

进入游戏只为当前有效选图建立元数据索引。图像文件经 IntersectionObserver 在接近视口时单条读取。相同存档实例中的多个组件共享读取、正在生成的缩略图和对象 URL，每次最多处理两个资源。缩略图最长边 256 像素，按解码后的方向等比显示。闲置缩略图按最近使用顺序淘汰，缓存目标为 24 项；正在使用的图像优先保留。查看完整图和导出使用原始文件；关闭预览释放大图，切档、关闭功能或时间线失效会清理缓存。解码失败回到文字或原人物标识。

## 长档实测

同一份存档含 300 个正式回合、300 张不同资源 ID 的剧情插画和 8 张其他用途图片。每回合将同一段叙事重复 12 次，剧情图的原始尺寸为 960 × 540。桌面及 Pixel 7 模拟使用单个 Playwright worker 依次运行。先在关闭功能时滚动 48 帧，再启用图片滚动相同的 4,320 个 CSS 像素，并跳到第 1、76、151、226、300 个回合。

| 实测指标 | 桌面 Chromium | 手机模拟 Chromium |
|---|---:|---:|
| 关闭时的图片文件读取 | 0 | 0 |
| 首屏读取图片文件 | 2 | 1 |
| 滚动及五次跳转后的累计读取 | 11 | 7 |
| 同时挂载的图片元素（跳转结束时） | 2 | 1 |
| 全库批量读取图片文件 | 0 | 0 |
| 关闭后的活跃图片对象 URL | 0 | 0 |
| 启用至首幅插画已解码 | 263 ms | 312 ms |
| 关闭／开启时的中位帧间隔 | 67／67 ms | 17／17 ms |
| 关闭／开启时的 P95 帧间隔 | 117／83 ms | 17／17 ms |

本次样本的中位帧间隔在两种模式下相同；桌面无头浏览器在纯文字模式下也出现较长帧。数字反映此运行环境和合成存档，无法据此推断所有手机的帧率。原始数据包含逐次跳转的缩略图等待时间及超过 50 ms 的帧数。[桌面数据](evidence/desktop-display-performance.json) · [手机数据](evidence/mobile-display-performance.json) · [运行日志](evidence/display-performance.txt)
