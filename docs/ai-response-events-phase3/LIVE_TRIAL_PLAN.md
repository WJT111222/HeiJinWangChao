## 建议最小样本

每个协议选择一个获准模型，测试普通文本/结构化输出 × 完整 JSON/SSE：四协议共 **16 次 Story 请求**。这只能筛查基础兼容，不能统计长期成功率或证明文学质量稳定。模型别名与接口可用性须以负责人实际账户为准，不能把 Mock 中的名称直接认定为已支持。

- 使用全新隔离存档、固定合成人物和同一组非敏感日常场景。
- 使用正式 Composer、完整 Prompt 与真实适配器，不裁掉世界书或更换提示词来制造兼容。
- 只调用 Story；不自动执行真实 Variables、World 或 Memory，不提交玩家存档。
- 每格只发一次，串行执行；不自动重试、不因拒绝/截断补样、不切换模型。
- 输出上限由负责人逐模型批准，不高于当前通道已有上限；若使用 8192 的批准上限，16 次的最大输出预算为 131072 Token，**仍不包含输入费用**。
- 原生 Thinking 与其他参数保持批准快照，不为满足工具模式而静默关闭、增大预算或改变温度。

## 记录与比较

每次记录真实状态码、真实结束原因、工具数量/名称/原生 ID 是否符合协议、原文/解析结果哈希、公开思考有无、严格验收结果、首次公开输出时间、首次小说可读时间、总耗时及供应商原始 usage 字段。

工具模式等待完整参数才展示小说，必须分别测首次网络输出与首次小说可读，不能只比较 SSE 第一帧。缓存、Thinking 和总输入统计按各协议定义记录，不将缓存细分再次相加，不用正文长度猜 Token，不把缺失 usage 当零。

同一上下文做文本/工具盲评：人物与场景一致性、自然叙事、行动自主性、事实与推测边界、摘要客观性、段落/对话、格式遵循。允许真实模型生成不同文本；不得使用 Mock 的字节相等作为文学评分，也不对 16 次小样本编造稳定率。

出现 HTTP 错误、过滤、输出上限、非法载体、未知结束、费用无法核对或超预算风险时立即记录并停止；保留真实原因，不以绕过安全控制为目标。失败后的重试和增加样本都要重新批准。观察费用以供应商实际账单为准，不能声称工具输出必然更省 Token。
