# Variables 与动态世界的局部容错结算

基线为 `main@553212ac2bc569cfcf19415f9a28225b092c4bdb`，包含 #198 的入场承接和 #200 的原始诊断位置。#201、#192 的开发分支独立。#202 的重叠处是浏览器用例，本分支更新产品行为断言，保留 #202 的分支与测试配置。

## 出站与解析

World 在同一个请求中返回下列三个顶层区块。开局和普通回合使用同一执行格式，Composer 的末尾提醒提供合法的空对象实例。请求适配器为 World 使用普通文本响应模式，原生推理字段独立收集。结构化 Memory 请求仍可使用供应商 JSON 模式。

```text
<thinking>核对到期事项、任务和后台组织，本轮没有需要更新的工作。</thinking>
<说明>当前排程保持原样。</说明>
<命令>
{"worldCommands":[],"taskCommands":[],"eventCommands":[],"visibleHooks":[],"unresolved":[]}
</命令>
```

只有完整、唯一的命令块进入可执行路径。规划摘要和说明留在临时原文，不能创建状态。前两段缺漏可以记录格式提醒。兼容完整的旧 World JSON；重验直接使用已保存的规范领域对象。标签冲突、截断、无法确定文本命令边界或损坏的外层 World 分组仍然拒绝。Variables 的扫描器追踪引号、转义和容器深度，多行值保持一个源位置。

## 筛选、依赖和原子事务

模型响应先按原始顺序建立命令位置。明确的已知失败只剔除自己的单元及下游依赖，创建失败会一并跳过引用新实体的后续动作。直接关联的任务和事件、结案和必要承接使用同组验证。相同数组索引和共享状态链一起校验。单条购买、转账和偿债使用既有复合命令，对于旧式独立余额变更与入库同时出现的保守组，任何一半失败就保留两边的原状态。普通的无主物品存储状态仍有效。新取得物品和购买物品的命令均要求 `ownerRef`。

筛选每次都从同一基线启动原有严格验证。失败尝试的内存副本被丢弃。错误位置精确时直接隔离该组。最终状态约束不能归属单条时，按依赖顺序验证可单独成立的组。世界时钟是后续操作共同的时间依据，无法建立合法基线时不会自行改成其他时刻。World 读取已接受 Variables 命令的实际投影和安全摘要，说明或淘汰的输入不参与投影。

本轮到期的既有子事件仅在其权威记录、原定时间和入场安排保持完整，并且没有同时改写后继时允许暂缓。合法结案仍须满足原固定时间和回执契约。暂缓只记录于候选和本回合结果；后续 World 根据原事件记录取得积压排程。省略必要结案时，结果也会标记待处理。在纯历史视角不推进当前排程。已存在的旧式到期事件同样只有保持原记录才能暂缓。

正式保存前，Repository 沿用草稿 CAS，重验同一接受集合和可暂缓事件并核对规范化结果，接着一次性写入。提交重验不会重新执行已丢弃的模型命令，也不会选第二份方案。模型输入严格拒绝程序的跳过和暂缓字段。草稿保存安全的跳过条目和暂缓标识，Journal 仅保留分类、原始序号、白名单字段、固定原因和计数。原文不进入 Journal。旧草稿和旧 Journal 缺少这些可选字段时继续读取。终态复述仍按 #200 的等价规则过滤。

## 体验与限制

结算结果在正文对应回合显示，可展开查看哪些更新未执行、哪些操作一起跳过，以及接受计数。全跳过与无变化可区分。跳过、暂缓或格式提醒本身不会阻止下一轮行动，也不会触发模型重发。不可读响应、传输中断、版本冲突、写库失败和不能形成一致投影的候选依旧报告失败。

业务语义无法从结构字段证明时，程序只使用已有的领域规则和保守的操作分组。Model 提出互相关联但没有任何可验证关系的任意两段剧情，程序不根据正文猜测交易。复合交易是表达不可拆业务的权威入口。发生大量隔离错误时，同一基线可能进行多次内存校验；正常候选走一次批量验证。Mock 验证了程序和已覆盖供应商协议，不用于推断真实模型质量。
