# 世界书 2.0：兼容参照与差异记录

本文件记录世界书 2.0 的兼容参照来源、版本和与参照版本的差异，随各阶段更新。

## 阶段 A：格式与字段

### 支持的输入

| 格式 | 识别方式 | 说明 |
| --- | --- | --- |
| 王朝世界书 | `format: "heijin-worldbook"` | 保留书 ID、版本 ID；重算内容哈希，对不上即拒绝 |
| 角色卡 V2 | `data.character_book` 存在，或 `entries` 为数组且条目使用 `keys` / `insertion_order` / `enabled` | 只导入世界书本身，角色卡其余内容不导入 |
| 酒馆世界书 | 有 `entries`（以 uid 为键的对象或数组） | 原文件整体保存为来源数据 |
| 角色卡 V3、NovelAI、Agnai、RisuAI、PNG 内嵌 | — | 明确报“暂不支持导入” |

### 条目字段

酒馆条目的字段与默认值按参照版本整理，规范化后的字段名见 `src/domain/worldbook/schema.ts`，对照表在 `src/domain/worldbook/entryFields.ts` 的 `MAIN_FIELDS`。

- `null` 表示“跟随全局设置”（扫描深度、大小写、完整词、分组评分、Sticky、冷却、延迟），导入时保持 `null`，不替它填值。
- 字段缺失或为 `null` 时取参照版本的默认值。
- 宽松读法只有两种，并且都会记警告：数字字段接受数字字符串（参照版本里它们按数字参与比较和排序）；真/假字段接受 0 / 1（参照版本按真假值判断）。其余类型不符一律报错，整本导入失败，不猜测。
- 文本形式的真/假值（如 `"true"`）不转换而报错：参照版本对它们的判断前后不一致（有的地方当真，有的地方当假）。
- 角色筛选、扫描角色卡文本（6 项）、向量检索、自动化 ID、`addMemo`、`displayIndex` 保留在 `inert` 里，只在原文件出现时才有，王朝不让它们生效。
- 其余未知字段只保存在来源数据里，导出酒馆格式时原样带回。

### 角色卡 V2 的换算

与参照版本导入角色卡世界书的取值方式一致，其中值得注意的几处：

- `selective` 缺省为 `false`（酒馆自己的条目缺省为 `true`）；
- `enabled` 取反得到“停用”，缺失时按停用处理；
- `position`：优先 `extensions.position`，否则 `before_char` 为 0、其余为 1；
- 其余高级字段都从 `extensions` 的下划线命名字段读取（如 `extensions.group_weight`）；
- 书级 `scan_depth`、`token_budget`、`recursive_scanning` 和条目级 `case_sensitive`、`name`、`priority` 参照版本不使用，王朝同样不使用，只记说明。

### 正则关键词

整个关键词形如 `/内容/标志`（标志只能是 g i m s u y）时按正则处理；内容里有未转义的 `/` 时不算正则；内容里第一处 `\/` 还原为 `/`；构造失败时按普通文本匹配。导入时用阶段 B 的安全子集编译一遍，不在子集内的写法记“暂不支持”提示；不拿它匹配任何文本。

参照版本每次匹配都新建正则对象，所以 `g` 不会造成状态残留；`y` 则只从扫描文本开头匹配（扫描文本以分隔符开头，通常永远不命中），导入时会说明。（阶段 A 初版把 `g` 也写成“时灵时不灵”，阶段 B 核对后更正。）

### 宏

`{{user}}` 等宏在关键词和正文里原样保留，导入时不执行。王朝现有的 `{{…}}` 请求校验不变；宏的解析与白名单在正文集成阶段单独设计。

### 身份与哈希

- 导入酒馆或角色卡文件时，每次新生成书 ID 和版本 ID，不按书名判断是不是同一本书。
- 内容哈希：对 `{ metadata, entries, source }` 做确定性 JSON（键按码点排序、无空白）后取 SHA-256。不包含书 ID、版本 ID、来源标记和兼容提示。
- 来源标记一律为 `local`；文件自称 `official` / `workshop` 无效。

### 导出

- **王朝格式**：版本本体原样写出，再导入时内容和哈希都不变。
- **酒馆格式**：来源是酒馆文件时，以原文件为底，保留书级未知字段、`entries` 的形状和键名、条目里的未知字段；只覆盖原来就有的字段和与默认值不同的字段。来源是角色卡时按完整字段写出新文件，并说明哪些角色卡字段不会出现在酒馆格式里。

### 与参照版本的已知差异（阶段 A）

| 项目 | 参照版本 | 王朝 |
| --- | --- | --- |
| 类型不符的字段 | 多数情况下原样存下，运行时按 JS 宽松规则处理 | 除上面两种宽松读法外一律报错，整本不导入 |
| 重复的条目 ID | 后者覆盖前者或行为不确定 | 两条都保留，王朝内部 ID 加后缀区分，并记警告 |
| 角色卡其余内容 | 属于角色卡本身 | 不导入，也不进入提示词 |
| 角色卡 V3、PNG 等 | 支持 | 暂不支持，明确报错 |

## 阶段 B：触发规则引擎

实现位于 `src/domain/worldbook/trigger.ts`（主流程）、`keyMatch.ts`、`safeRegex.ts`、`timedEffects.ts`、`triggerSupport.ts`。引擎是纯函数：输入书籍版本、可扫描消息、设置、计时状态和随机种子，输出激活条目、插入计划、每个条目的判定原因、预算使用和下一份计时状态。它不读写存档、不联网、不调用模型。

### 扫描流程（与参照版本一致）

1. 所有绑定书的条目合并，按 `order` 从高到低稳定排序；解析正文开头的前缀指令。
2. 逐轮扫描。每轮按排序检查每个尚未激活、本次未掷失败的条目，依次判断：停用 → 触发模式 → 延迟 → 冷却（Sticky 中不受冷却影响）→ 延迟到递归 → 不可被递归 → `@@activate` / `@@dont_activate` → 常驻 → Sticky → 主关键词 → 副关键词逻辑。
3. 本轮候选排序（Sticky 优先，其余保持扫描顺序）→ 分组互斥 → 逐条做概率检定与预算判断。
4. 是否继续：开启递归且未超预算、有可递归的新条目时继续；最少激活数未满足时加深一条扫描；还有未处理的“延迟到递归”层级时进入下一层级。
5. 插入计划按 `order` 从高到低处理，同一位置内 `order` 越大越靠后（越接近生成点）；正文为空、未知位置、Outlet 无名称的条目激活但不插入。

### 关键词匹配

- 扫描文本：最近 N 条消息（每条去掉首尾空白）以分隔符拼接，加上递归缓冲（最少激活数的加深扫描不含递归缓冲）。深度为 0 或负数时不扫描，上限 1000 条。
- 普通文本：不区分大小写时两边转小写后做包含判断；完整词模式下，不含空白的关键词要求两侧是文本边界或非 `[A-Za-z0-9_]` 字符，含空白的直接做包含判断。**对中文基本等同于包含匹配**，与参照版本一致，不另做中文分词。
- 只由空白组成的关键词去掉空白后是空串，会匹配任何文本（参照版本行为）。
- 副关键词逻辑：AND ANY（任一命中）、NOT ALL（任一未命中）、NOT ANY（全部未命中）、AND ALL（全部命中）；未知取值永不满足。
- 分组评分：命中主关键词数；有副关键词时，AND ANY 加上副关键词命中数，AND ALL 在副关键词全中时才加。评分不做宏替换和去空白（参照版本如此）。

### 前缀指令

只有正文以 `@@` 开头时才解析：逐行读，直到第一行不以 `@@` 开头，其后为正文。以 `@@activate` / `@@dont_activate` 开头的行是已知指令；未知指令丢弃；以 `@@@` 开头的行在前一行是未知指令时去掉一个 `@` 再判断，否则忽略。如果每一行都以 `@@` 开头，正文保持原样。只有与 `@@activate` / `@@dont_activate` 完全相同的行才生效。

### 分组互斥

组名按逗号拆分，一个条目可属于多个组。顺序：有 Sticky 的组只留 Sticky 条目，冷却 / 延迟中的条目移出 → 分组评分（开启时只留最高分）→ 同组已有条目在之前轮次激活则全组作废 → 有优先条目时取 `order` 最高的 → 否则按权重随机抽一个。

### 概率与随机数

`useProbability` 为真且概率不是 100、且不在 Sticky 中时掷 0–100 的随机数，掷出值不超过概率即通过；失败的条目本次不再参与。随机数来自调用方给的种子（例如“存档 + 回合 + 第几次尝试”），同一种子结果完全相同，因此**预览与正式生成一致，预览不消耗随机状态**。随机序列与参照版本不同（参照版本用 `Math.random`），规则相同。

### 与参照版本的差异（阶段 B，均为有意的王朝适配）

| 项目 | 参照版本 | 王朝 |
| --- | --- | --- |
| 正则关键词 | 用 JavaScript 正则直接执行 | 只运行可验证的安全子集（自写线性时间匹配器，与原生正则做差分测试）；u / v 标志、前后瞻、反向引用、`\p`、八进制、超大重复等不运行，按不命中处理并在结果里列出 |
| 计时单位 | 聊天消息条数；组装请求时就写入状态 | 逻辑消息数：每个成功结算的回合 +2，生成当前回合时 +1（本回合玩家行动）。引擎只返回下一份状态，**只有回合正式结算才保存**；取消、失败、重试、预览都不推进。这是王朝适配语义，不宣称与酒馆所有聊天操作（删消息、编辑、换页等）完全等价 |
| 预览时的计时效果 | 预览（dry run）不读取 Sticky / 冷却 | 预览按真实状态计算，结果与正式生成一致，但不改变状态 |
| 预算 | 上下文 × 百分比，可设上限；“无视预算”的条目不受限制 | 软预算按参照版本：上下文 × 25%，达到即超出。另加**王朝硬上限** = min(合计上限 4096, Story 实际剩余输入预算)，按实际注入总量计算，对所有条目生效（包括“无视预算”的条目），保证不会因世界书导致请求超长；剩余预算为 0 时不注入任何条目 |
| Token 计数 | 模型分词器 | 保守估算：ASCII 每 3 个字符 1、其余字符每个 1.5，向上取整；每条另加 1 计分隔 |
| 多组条目被重复移出 | 第二次移出时误删列表最后一个无关条目（缺陷） | **有意修正**：条目已不在列表中时什么也不做。有回归测试 |
| 同组已激活判断 | 拿已激活条目的完整组字符串与单个组名比较，多组条目可能不被识别 | 照此实现（兼容），有测试 |
| 角色筛选、扫描角色卡文本、作者注释等注入文本 | 参与 | 王朝没有对应内容，不参与 |
| 消息带发言人名字 | 默认以“名字: 内容”参与扫描 | 由调用方决定消息文本格式（正文集成阶段确定） |
| 宏 | 关键词与正文先替换宏 | 默认不替换；提供替换钩子，宏解析与白名单在正文集成阶段设计 |

### 默认设置

扫描最近 2 条逻辑消息；预算为上下文窗口的 25%；所有新增可选世界书合计上限 4096 Token，且不超过 Story 实际剩余输入预算；递归关闭；不区分大小写；不启用完整词与分组评分；最大递归步数与最少激活数为 0（不限 / 不启用）。阶段 B 通过参数传入，阶段 C 起按存档保存。
