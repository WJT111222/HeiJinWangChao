## 原则

- **只改 ≤900px。** 电脑端照旧按以下文档实现：`CHANGES_HANDOFF.md`、`FEEDBACK_HANDOFF.md`、`TOOLS_HANDOFF.md`。
- **不变的部分：** 显示条件、文案、`role`、`aria-label`、`data-testid`、键盘逻辑，全部和电脑端一致。只换容器和排版。
- **四个级别的颜色**沿用 `FEEDBACK_HANDOFF.md`：

  | 级别 | 深色 | 档案纸 |
  |---|---|---|
  | 错误 | `#D47C60` | `#A3412E` |
  | 注意 | `#E0C27A` | `#8E6C25` |
  | 说明 | `#8EC1E0` | `#2D5E7D` |
  | 完成 | `#7DBB9C` | `#2F7A58` |

## 1. 本回合变化（深色全屏抽屉）

- **入口：** 主界面最新回合末尾的「本回合变化 N 项」按钮。手机上不在原地展开，而是从底部升起一个全屏抽屉，保留 `aria-expanded` 和 `aria-controls`。
- **标题栏：** 「变」字方印，eyebrow 写「THIS TURN · 第 N 回」，标题为「本回合变化」。
- **汇总行：** 金色等宽大数字「N」，后面跟「项变化」，右侧是分类色点。
- **分组卡：** 单列排列。卡头依次为色点、分类名、条数。
- **条目：** 每条是一个按钮，内容分两行：
  - 第一行：左边是对象（字段名放在对象名后面，颜色较暗），右边是数值或标签。
  - 第二行：灰色小字，写「旧 → 新」或简介。
  - 可以跳转的条目，右下角显示「›」。
- **数值写法：** 和电脑端一致——数字涨为绿、跌为赭红；时间写成删除线旧值加新值；标签分三种：获得或新增为绿，变更、离场或新阶段为金，失去或移除为赭红。
- **点击条目：** 先关闭这个抽屉，再打开对应面板的抽屉，并定位到那条记录。
- **超过 8 条：** 显示「还有 N 条」，点击展开。
- **底部小字：** 原文不变。
- **无法比较或没有变化时：** 和电脑端规则相同，按钮置为 disabled，不弹出抽屉。

## 2. 全局提示条（`.app-error`）

- **位置：**
  - 游戏内：在城市胶囊下方，左右各留 12px，不推动正文，层级高于抽屉。
  - 首页（车票）：贴在安全区下方 6px。
- **外观：** 深色卡片，左边一条 3px 错误色竖条，接着是「误」圆标和文案，右侧是 ×（`aria-label="关闭提示"` 不变）。
- **逻辑：** 不变。同一时间只显示一条，不自动消失。入场时从上方 8px 滑下，用时 0.3s。

## 3. 小确认弹窗 → 底部操作表

撤回上一回合、记忆总结失败 / 待确认、删除存档，这几个 `Dialog small` 在手机上统一做成**底部操作表**。

- **主卡片：**
  - 顶部 3px 级别色条。
  - 单字方印带级别色：撤、忆、删。
  - 标题用衬线字。
  - 下面依次是：结论、后果列表（小圆点）、灰色补充说明，弹窗内的报错用 `.alert`。
- **操作行：** 在主卡片下方，**整行宽、上下排列**，主操作放在最上面。
  - 危险操作（确认撤回、确认删除）：赭红字，加粗。
  - 主操作（重新生成、前往设置选择人物）：金字，加粗。
  - 次要操作：普通字。
- **取消类按钮**（保留当前回合、取消、关闭）：单独放在最底下一张卡片里，最靠近拇指。
- **原有逻辑不变：** 禁用条件、执行中的文案（「正在撤回…」「正在删除…」）、× 关闭、Esc。
- **设置内的「AI 配置尚未保存」：** 用档案纸版，见 `MOBILE_PANELS_HANDOFF.md` 第五节第 6 条。

## 4. 游戏菜单（新补）

仓库里手机端顶栏有一个 `.mobile-menu-toggle`（☰），点开是 `Dialog title="游戏菜单" small`，里面有：游戏首页 / 切换存档 / 设置 / 版本号。

- **☰ 按钮：** 放在城市胶囊右侧，做成 2.75rem 的圆形按钮，胶囊相应变窄。打开时按钮描金。`aria-label="打开游戏菜单"` 不变。
- **菜单：** 用底部操作表。
  - 三行分别是「首」游戏首页、「票」切换存档、「设」设置，每行前面一个小方印（新增装饰）。
  - 卡片底部是灰色小字「黑金王朝 · 版本号」，版本号取 `PRODUCT_VERSION`。
  - 下方单独一张「关闭」卡片。
- **行为不变：** 「游戏首页」和「切换存档」都执行 `navigate()`；「设置」打开设置。

## 5. 通用控件（设置内，档案纸）

### ThemedSelect → 底部选择器

- **触发器：** 和电脑端一样：浅纸底，右侧是金色 ▼ 小方块；展开时描金边，▼ 旋转 180°。
- **点击后：** 不在原地弹出浮层，改为**从底部升起选择器**，最高 72% 屏幕高度。
  - **标题栏：** 「选」字朱砂方印，eyebrow 写「SELECT · 字段名」。
  - **可搜索时：** 顶部是搜索框，字号 16px。
  - **选项：** 每个至少 44px 高。
    - 当前项（`option-active`）：浅金底，左侧 2px 金条。
    - 已选项（`aria-selected`）：加粗，右侧显示金色 ✓。
    - 搜索时，匹配到的文字用 `<mark>` 高亮。选项文字要用一个 `<span>` 包起来。
  - **模型列表：** 依次是「使用渠道默认模型」、分组标题「渠道模型」、各个模型。输入搜索词后隐藏分组标题，没有匹配项时显示原文案。
- **键盘和读屏：** 逻辑不变——方向键、Home、End、Enter、Esc、`aria-activedescendant`。只把浮层容器换成底部抽屉，抽屉挂在当前 dialog 内。
- **关闭：** 选中一项后自动关闭；点遮罩或往下拉也可以关闭。

### ModelPicker

- **第一行：** 下拉触发器，右侧是「↻ 刷新模型」按钮。获取中时图标旋转，按钮禁用。
- **第二行：** 状态圆点加 `list.message`（`role="status"`），颜色规则同电脑端。
- **第三行：** 「手动填写X模型 ID」是蓝色文字链接，点开后出现虚线框，里面是等宽输入框。

### OutputTokenLimit

- 选择「自定义」后，下方出现虚线框，里面是数字输入框，带「Token」后缀，`inputmode="numeric"`。

## 6. 诊断抽屉（重试与变更详情）

- **入口：** 三阶段抽屉里的「重试与变更详情」，有错误时后面带「错误 N」胶囊。点击后从底部升起一个**全屏深色抽屉**，不在三阶段抽屉里原地展开。
- **分类：** 电脑端的左栏改成顶部横滑标签：概要 / 运行日志 / 请求用量 ｜ 模型原文 / 叙事规划，`role="tablist"`。
  - 数字角标：运行日志后面的错误数用赭红实心，请求用量后面的数字用灰色。
  - 选中的标签为金色实心。
- **底部小字：** 「仅本页临时保存 · 刷新即清空」，放在内容最底部。
- **行为：**
  - 新错误到达时，自动打开抽屉并切到「运行日志」。
  - 模型原文和叙事规划只在切到对应标签时才渲染。
  - `data-testid` 保留在对应面板上。
- **运行日志卡片：**
  - 左边 3px 赭红竖条。
  - 头部依次为：时间（等宽字）、阶段、「错误」标签，右侧是「复制此条」。
  - 下面是 message。
  - 最下面是两列键值表；手机上字号 0.72rem，值可以换行。
- **概要：** 三张小指标卡排成一行。
- **请求用量：** 每次请求一张卡，四个用量小格改为 2×2。
- **代码框：** 模型原文、叙事规划里的代码框，最大高度改为 12rem，横向不溢出，长行自动换行。

## 7. 变量候选 / 世界候选（全屏）

- **入口：** 「查看变量候选（未结算）/ 查看世界候选（未结算）」，打开后是全屏深色抽屉。
- **头部：** eyebrow「STAGE 02 · VARIABLES」或「STAGE 03 · WORLD」，标题沿用原文，下面一行是状态胶囊（颜色规则同电脑端）。
- **版本号：** 正文版本、执行版本、候选版本，三个小块，可以横向滑动。
- **三张计数卡**（合法命令 / 拒绝建议 / 未解决事项）：并排一行。数字来自原句，含义不变。点击某张卡会把列表滚动到对应位置（可选，不做也可以）。
- **候选列表：**
  - 分节标题沿用原文。
  - 每行左侧是类型标签（等宽字，带底色）：普通为蓝，拒绝为赭红，未解决或缺失为金。
  - 标签右侧是说明，下方是命令 ID（灰色等宽字）。
- **原始响应：** 「主动查看 / 隐藏完整变量候选」是蓝色文字链接，展开后是黑底等宽代码框，最大高度 12rem。
- **底栏：** 固定在底部，只放「关闭」（与 × 相同）。原弹窗里有的其他按钮也放在这里，没有的不新增。

## 验收

1. 每个提示和确认的触发位置不变；手机上按本文档显示，危险操作和取消都在拇指够得到的范围内。
2. ThemedSelect 底部选择器的键盘操作、读屏朗读、点遮罩关闭都可用；e2e 只调整选择器。
3. 本回合变化的每一条都能跳到对应面板；拿不到结算前状态、没有变化时，规则和电脑端一致。
4. 诊断：新错误自动切到运行日志；复制此条、清空日志可用；不会额外请求模型。
5. 游戏菜单的三个入口和版本号都在，行为不变。
6. 375×667 下没有横向溢出；reduced-motion 下没有动画。
