# 手机端 · 开场（车票） 交接文档

设计稿是 `heijin-mobile-home.html`。用手机打开会全屏；在电脑上打开，会显示一个机身框，右侧是演示控制。

可以用 hash 直接打开某个状态：

- `#i=N`：停在第 N 张车票（从 0 开始）
- `#list=bad|empty|loading|error`：存档列表的几种状态
- `#draft=0`：没有创角草稿
- `#tear`：票根正在被撕开
- `#del`：删除确认

## 核心概念

手机端**不再分「封面」和「存档馆」两页**，两者合成一屏：每份存档就是一张开往某座城市的车票。

- **横滑**翻车票。
- **撕下票根**进入游戏。
- **最后一张**是「空白车票」，用来开启新的人生。

## 原则

- **只改 ≤900px。** 电脑端照旧使用 `HOME_SCREEN_HANDOFF.md`。
- **功能、数据、disabled 条件都不变。** 包括：开始新游戏、继续游戏、读取、选择、删除、导出原始数据、刷新列表、须知、公告、设置、草稿提示、`saveNotice`、`listError`、空状态和删除确认。手机上一个都不能少，只是换了承载方式。
- **城市推断**沿用电脑端的规则：从 `title` 的城市后缀推断。推断不出来时用中性票头（见下文「无法推断城市」），不显示城市名。
- **新增的装饰性文案**如下，都只在手机端出现，不进存档：

  | 位置 | 文案 |
  |---|---|
  | 计数 | 车票 NN |
  | 车票 | FROM / TO、单程、保存日期、时刻、存档 本地；底纹带的经纬度（意象词沿用电脑端封面） |
  | 检票章 | 已检票 SELECTED、无法读取 |
  | 空白车票 | 空白车票 NEW LIFE、城市 ___、职业 ___ |
  | 票根 | ↓ 按住票根往下撕 |
  | 发车屏 | 终点 DEST、已选择、本地存档、可购票、无法读取、读取中、暂停检票 |

## 页面结构（从上到下）

| 区块 | 内容 |
|---|---|
| 顶栏 | 品牌印章「黑」、黑金王朝、「设置」、`V1.0` |
| 标题 | MODERN CITY / OPEN WORLD、黑金王朝（金色渐变）、「起点有冲突，人生不预设结局。」 |
| **翻牌发车屏** | 当前这张车票的终点、时刻、状态 |
| 计数行 | 「车票 NN」「本地保存 · 无需账号」「刷新列表」（读取中时 disabled） |
| **车票栏** | 横滑卡片，下方有页码点 |
| `saveNotice` | 绿色状态条，`role=status` |
| 操作区 | 跟着当前车票变化（见下表） |
| 底部 | 「游玩须知与免责声明」「王朝公告」，以及两行原有脚注 |

整页可以纵向滚动。在 375×667 这样的小屏上，只要往下滚就能看到全部内容。

## 车票排序

- **当前选中的存档固定排第一张**，所以打开首页就停在它上面。这张车票等同于电脑端的「继续游戏」。
- 其余存档按现有顺序排列。
- 「空白车票」永远是最后一张。

## 翻牌发车屏

| 当前车票 | 终点 | 时刻 | 状态 | 状态颜色 |
|---|---|---|---|---|
| 已选择的存档 | 城市名 | 保存时刻 | 已选择 | ok 绿 |
| 其他存档 | 城市名 | 保存时刻 | 本地存档 | 灰 |
| 空白车票 | 新人生 | --:-- | 可购票 | 金 |
| 无法读取 | 未知 | --:-- | 无法读取 | err |
| 读取中 | ··· | --:-- | 读取中 | 灰 |
| 读取失败 | ——— | --:-- | 暂停检票 | err |

- 每个字一块翻牌，上下两半之间有一条分缝。
- 只有内容变了的那几块才翻动，每块依次错开 60ms。
- 整块屏用 `aria-live="polite"`。

## 车票

### 尺寸

- 宽度占屏幕的 82%，高度 340px。用 `scroll-snap` 居中吸附。
- 两侧的车票缩小到 0.9，变暗，并朝外倾斜 3°。

### 结构

1. **票头 42px**：城市名、英文名、`ARCHIVE NN`。
2. **路线**：FROM 人物名，TO 城市名，中间写「单程」。
3. **信息行**：保存日期、时刻、存档 本地。已选择的车票不显示「存档 本地」，那个位置让给检票章。
4. **城市底纹带（74px）**：车票上**不用天际线剪影**。改为：
   - 底纹：15 条叠加的正弦波浪线（防伪纹），城市色、线宽 0.7、透明度 .55，每隔 4 条加深一条。波形参数由城市种子决定，保证每次渲染都一样。算法见设计稿里的 `guilloche()`。
   - 左上：经纬度（等宽字，城市色加深）。左下：三个意象词（衬线）。两处文字都垫一块纸色底，压在底纹上。
   - 右侧：城市简称圆章（渝 / 沪 / 冰 / 穗），双圈，城市色加深。
   - 经纬度和意象词与电脑端封面的城市元信息是同一套数据，建议放在同一个常量里。
5. **撕线**：一条虚线，两端各有一个半圆缺口。
6. **票根 72px**：主文案、「↓ 按住票根往下撕」和条形码。

### 人物名

`SaveSummary` 里没有单独的人物字段，就取 `title` 中「 · 」前面的部分。如果拆不开，FROM 就显示完整的 `title`。

### 四城票头

和游戏内的回目铭牌对应：

| 城市 | 票头样式 |
|---|---|
| 重庆 | 绿底 `#2f6f63`，底部一条轻轨虚线 |
| 上海 | 搪瓷蓝 `#34468e`，内描一圈白边 |
| 哈尔滨 | 冰蓝渐变，深色字，带霜点 |
| 广州 | 深底，橙色霓虹字（发光） |

### 无法推断城市

车票照常显示，按下面处理：

| 位置 | 显示 |
|---|---|
| 票头 | 中性灰褐色（`#5b5048`） |
| 票头城市名、TO | 留空 |
| 城市底纹带 | 灰褐色底纹，不显示坐标、意象词和圆章 |
| 发车屏终点 | 和「无法读取」一样显示「未知」 |
| 发车屏时刻、状态 | 不变 |

### 已选择的车票

右上角盖一枚朱砂色的圆形检票章「已检票 SELECTED」，旋转 −14°，`mix-blend-mode: multiply`。这个章对应电脑端的回形针和「已选择」标签。

### 空白车票

| 位置 | 内容 |
|---|---|
| 票头 | 金色斜纹 |
| FROM / TO | 灰色「？」 |
| 信息行 | 「城市」「职业」两条空白下划线 |
| 中部 | 「四座城市 · 自由职业 · 开放人生」 |
| 草稿 | 有草稿时，在中部下面加一行手写感（略微倾斜）的「✎ 有尚未完成的创角资料，可继续填写」 |
| 票根 | 「开启新的人生」 |

### 无法读取的存档

| 位置 | 内容 |
|---|---|
| 票头 | 灰褐色「未知 UNREADABLE」 |
| FROM | 显示 `title` |
| 原字段 | 存档记录 ID、内容中的存档 ID、说明文案，全部保留 |
| 印章 | 「无法读取」朱砂章 |
| 票根 | 只显示「保存时间无法读取」，不能撕 |

### 删除后

确认删除以后，车票盖上一枚放大的「作废」章，然后从列表中移除。设计稿只演示到盖章这一步。

## 撕票根（核心交互）

- **触发：** 在票根上按住往下拉，用 pointer 事件并 `setPointerCapture`。拉的过程中，票根以右上角为轴向下转动。
- **成功：** 超过 60px 松手就撕下。票根下落、旋转、淡出，用时 0.5s，同时触发震动 `vibrate([10, 30, 18])`。约 0.7s 后：
  - 普通车票：执行「读取存档」，和对应按钮是同一个方法。
  - 空白车票：执行「开始新游戏」。
- **未达到：** 不到 60px 松手就回弹。
- **撕开后的样子：** 车票纸面只到撕线为止，票根本身单独铺纸色背景。所以撕开后，原来票根的位置露出的是页面背景，不是一块空白纸。
- **按钮等价：** 金色主按钮做的事和撕票根完全一样（设计稿里点按钮也会播放撕票动画）。**按钮不能省**，键盘和读屏用户靠它操作。
- **reduced-motion：** 不播放撕票动画，直接执行。

## 操作区（跟随当前车票）

| 当前车票 | 主按钮（金） | 次要按钮 |
|---|---|---|
| 已选择的存档 | 继续游戏 → | 删除 |
| 其他存档 | 读取存档 ↗ | 选择 · 删除 |
| 空白车票 | 开始新游戏 ↗ | — |
| 无法读取 | — | 导出原始数据 · 删除存档 |
| 读取失败 | 开始新游戏 ↗ | — |

- **其他情况的主按钮：** 如果现有逻辑要求「开始新游戏」在任何时候都能点（没有 repository 时除外），那么除了上表已列出的空白车票和读取失败，其余情况下，点主按钮所在区域的入口应先滑到空白车票，再点一次才开始。设计稿就是这么做的：`[data-new]` 不在空白车票上时会先滚过去。
- **选择后：** 那张车票会成为第一张，盖上检票章，车票栏回到第一张。
- **删除：** 打开底部操作表，内容依次是：3px 朱砂顶条、标题、原文案、存档记录 ID，下面是「确认删除」，再单独一块「取消」。文案和逻辑逐字沿用现有的删除确认框。

## 其他状态

- **读取中：** 两张深色骨架车票（扫光动画），下面一行「正在读取本地存档…」。
- **读取失败：** `err` 提示框，内容是 `listError` 的原文。下方保留「开始新游戏 ↗」。
- **空：** 只有一张空白车票，页码点下面显示原有的空状态文案。
- **禁用：** 没有 repository 时，空白车票的票根不能撕，「开始新游戏」也设为 disabled。

## 无障碍

- 每张车票都是一个 `<article>`，带 `aria-label`，例如「沈砚 · 重庆，保存于 2026/11/10 23:41，已选择」。
- 车票栏获得焦点时，可以用左右方向键切换车票。
- 底纹带、印章和条形码都加 `aria-hidden`。
- 操作表打开时，焦点落在操作表容器上；按 Esc 或点遮罩关闭。

## 验收

1. 在 375×667、390×844、430×932 三种尺寸下，车票、按钮和底部链接互不遮挡。
2. 现有的所有功能入口和状态文案都还在。e2e 只调整选择器。
3. 撕票根和主按钮调用的是同一个方法。不能撕的车票（无法读取、没有 repository）不响应拖动。
4. 翻牌屏只翻动变化的字。reduced-motion 下没有任何动画。
5. 打开首页时，停在当前选中的存档上。
