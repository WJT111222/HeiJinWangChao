## 玩家入口与启动顺序

在「设置 → 运行 → 正文预设」选择内置包，保存并刷新。页面先捕获原始 fetch、安装第二批分派器，再按启用的来源、文件夹、脚本与实例 ID 排序执行。每个实例都有同源 iframe、父页面 jQuery、Lodash 和自己的实例 API。普通脚本等待执行，模块等待所属 iframe 的动态 import 求值完成，包括顶层 await；随后等待通过助手登记的 jQuery 就绪任务。React 重挂载、返回首页、切换存档都沿用本次页面启动的实例。[页面启动](../../src/main.tsx) · [加载器与接口](../../src/presets/tavern/scriptHost.ts)

首次生成等候初始化，随后定格生效的预设配置。渠道、凭证和玩家输入沿用正式请求入口的快照。正在生成时，保存配置只影响后续主动请求。切换或关闭预设前须先完成或取消当前操作，游戏在会话存储中按存档实例、回合和草稿版本暂存未提交输入。保存失败留在当前页面。`?safe=1` 在执行脚本前生效，可关闭异常预设，配置损坏时可显式重置酒馆偏好。[启动、刷新与状态](../../src/presets/tavern/hostState.ts) · [StoryStage](../../src/workflows/storyStage.ts) · [设置入口](../../src/ui/settings/TavernAssistant.tsx)

## 助手接口与边界

| 接口 | 本批语义 |
| --- | --- |
| getContext、SillyTavern、TavernHelper、getPreset、getLoadedPresetName | 上下文外层按调用取得；chatCompletionSettings 在本页共享引用。getPreset 返回独立副本、顺序表中的条目、未使用项、采样配置和扩展，其中发送正则转换为助手的公开字段。 |
| 保存与快照 | 支持条目内容及开关、四个采样字段、工具开关与 system 合并设置。实时修改可进入下次请求副本；saveSettingsDebounced 排队保存到第一批覆盖层，切换前同步完成待保存工作。promptManager.render 更新设置内可见的启用条目数。 |
| 事件和工具 | 正式出站使用第二批事件内核。提供 on、once、first、last、remove、clear、stop，两种 emit 沿用既有等待及失败处理。实例拥有自己的监听及按钮事件；同名工具按名称替换。回查得到真实注册对象及 toFunctionOpenAI 方法，shouldRegister 为 false 仍可供脚本识别，由脚本决定是否在请求准备事件加入。 |
| 身份、变量和楼层 | 全局、预设、脚本变量分别保存在本地预设偏好中。默认 chat 作用域；聊天／楼层临时变量绑定当前存档上下文，楼层按版本失效。历史读取仅提供当前王朝资料、可取得的逐字行动和正文。脚本树读取支持 preset，首版无其他可运行来源。 |
| 预览与库 | 游戏内干跑接入 previewTavernStory，返回正式组装并发预览事件。Token 数为游戏现有估算。助手不提供脚本主动付费生成。jQuery 3.7.1 与 Lodash 4.17.23 随包加载，类型依赖及许可一并更新。 |
| 诊断和按钮 | 「设置 → 运行」列出每个实例的加载、出错、停用、版本及观察到的脚本状态。桌面正文工具栏和手机三阶段抽屉读取同一份运行时按钮；脚本自行绘制的状态面板显示资料整理及输出方式。真实上游状态、事件边界和 usage 继续来自阶段诊断。 |

## 可复核的 Mock 证据

桌面和手机 Chromium 从实际包加载脚本。测试只提供合成游戏资料及上游响应，包内脚本自行发现标记、改写请求、消费工具参数。桌面用 1440 × 1000，手机用 Playwright Pixel 7 配置。

| 检查点 | 浏览器观测 |
| --- | --- |
| 原作者的请求与响应路径 | 两次主动生成的上游都出现 wave_context_reference、actual_content 两个工具。前者的说明包含当前合成人物，末条指令出现交付工具。分别交付工具 JSON 和 SSE 参数，严格校验后 Repository 读回相同正文。独立上游计量分别保留 17 和 19 个输出 Token。 |
| 取消、续写、监听器出错 | 第三次生成在等待 Mock 时取消，原草稿和正式 revision 保持原值。再主动生成，请求流式、上游返回完整 JSON，也能保存。续写发出 continue 类型，真实脚本跳过工具，下一次监听器出错在传输前终止。六次主动操作合计五次上游传输。 |
| 真实游戏按钮和切档 | 在两份合成存档点击「生成开局正文」，上游工具说明分别携带该存档人物，普通正文均可保存。第三次返回相似名称的未处理工具，阶段报 invalid_output，前一合法草稿及正式状态逐字段相同。刷新恢复未发送的行动，停用不产生传输。 |
| 保存和旁路 | 通过真实脚本上下文把温度设成 0.37，保存、刷新，实际下一次请求带 0.37。另一用例在等待上游时改为 0.23，原请求仍为 1，下次才发 0.23。脚本加载前后的 Variables、World、Memory 及原生 Story 比较完整出站请求，干跑额外调用数为零。 |
| 启动和恢复 | 合成模块显式等待顶层 await，首次 Story 等待时取消得到 cancelled、零传输。随后模块故意抛错，实例显示具体错误，再次生成报 configuration，草稿及正式版本保持原值。接口夹具还覆盖模块／普通脚本顺序、禁用文件夹、跨 iframe Request、按钮归属、重入与 once、工具回查、不同变量作用域。 |
| 故障处理 | 预设保存故障可见，页面保留；safe 模式零实例，可在玩家明确操作后清除损坏的预设偏好。真实模型未调用。 |

## 复验与剩余范围

Node 24.19.0、npm 11.9.0、Vitest 5.0.5、Playwright 1.64.1，桌面及手机视口使用 Chromium 154.0.8037.57。运行 npm ci、ESLint、TypeScript、Vite Build、文件名检查、命令目录检查及 git diff --check。15 个定向 Vitest 文件共 490 项通过，包含第一批参数兼容、四协议、续写、取消、CAS 和 #203 部分结算。最终定向 Chromium 共 12 项通过（桌面、手机各 6 项），每个项目含 5 项新增场景和 1 项第二批回归，0 失败、0 跳过。未运行全量浏览器套件。GitHub Actions 的全量成绩按最终提交单独列在 PR 验收留言。

前期一轮同时运行编译、Vitest 和浏览器，桌面长场景达到默认 30 秒，总计 9 通过、1 超时。跨存档新用例首次引用了错误的测试导入名，在两个项目中均失败；改用正式的 readAiConfig 后复验。保留默认超时、重试次数和业务断言。

真实脚本端到端验收覆盖 OpenAI 兼容 Mock。DeepSeek、Gemini、Anthropic 本批有既有虚拟后端协议测试，尚未跑三者各自的完整真实脚本浏览器矩阵。手机为桌面 Chromium 设备模拟；真机和真实供应商行为未验证。完整条目设置、控制台引导及全部互斥编辑、专用酒馆 DOM（例如输入框 #send_textarea）、导入方案均未作整包兼容承诺。当前设置支持编辑已有条目，改变顺序会报错。完整热卸载、玩家预设导入、附页和脚本主动发起正式生成不在本批内。
