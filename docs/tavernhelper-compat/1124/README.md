100001 顺序表采用零起点时，1118 的资料边界为 140–151，包含世界书后槽与历史。1124 的边界为 153–156，紧随 152 的 `worldInfoAfter`。源码按边界处理发送副本。宏在每次组装时展开，角色、随机选项和本文变量沿用现有宿主。历史正则只作用于本次发送的 assistant 副本。[实际出站索引](wire-index.json) · [脱敏 Mock 请求体](mock-requests.json.gz)

索引以预设版本、协议、流式标志和设备定位每次发送。解压 `mock-requests.json.gz` 后，数组中每条记录的 `body` 字段保存原始请求字符串；取其 UTF-8 字节计算 SHA-256 即可与索引比对。测试只保存合成人物、行动和模型请求体，未写入 HTTP 头或会话凭据。

## 功能取舍

| 上游功能 | 王朝处理 |
| --- | --- |
| 文学条目 | 保留 146 个完整原条目。改编 1 个交付条目，保留六段文学规划并对接正文、短期记忆及变量规划协议。21 个与请求干预、附页或独立业务写入相关的条目锁定关闭。 |
| 新版选项 | 新增的防霸总化、意识流和古风仙子文风进入控制台。意识流固定第一人称和黑箱心声，关闭纯对白，切换文风后可继续调整。天气和生理附页以锁定条目保留来源身份。 |
| 主脚本 | 从 1124 固定原件提取资料说明、近期历史清理、正文计数和规划处理。模型传输、错误检查和内容还原沿用经审查的王朝版。没有引入上游的混淆路由、外部日志和拒答干预。 |
| 潮汐控制台 | 88 项文学菜单、互斥分组、条目编辑、自定义创作槽、四项采样与交付偏好。已保存配置的 Token 数为本地估算。原格式文学方案支持本地保存、载入、重命名及 JSON 导入导出。导入仅应用开放菜单中的条目。 |
| 视觉与交互 | 日潮、夜潮分别保存背景色与按钮色。保留原件港口人物标识、经典波浪以及本地背景图。王朝桌面工具栏、手机抽屉和自适应设置面板承接酒馆悬浮窗入口与编辑交互。 |
| 主线时序 | 原脚本会读取和改写聊天消息。王朝版按钮打开只读视图，列出当前存档的正式时钟、最近记录及可核对的场景时间差。视图跟随页面的正式状态，即使面板保持打开也随存档切换。没有独立计时和写入入口。 |
| 渠道、变量、记忆、世界书 | 来自当前正式存档和游戏渠道配置。酒馆渠道向导、附页、外部日志、第三方前端 HTML 注入与 SPreset 扩展由原件审计清单留档。 |
| 断点、权限和结算 | 1124 使用公共预设注册项和文学配置投影，快照、有效配置指纹及断点继续使用 #247 的规则。原生模式和独立防截断继续使用原先的文学设置与脚本。正式结算使用现有事务及提交回执。 |

原控制台目录有九组，含“进阶调节”和附页。本版开放八组共 88 项，原件的 11 个互斥组均映射到相同的文学选项。原控制台仍引用 `wave-thinking-tail`，1124 原件已无对应提示词。源码里独立选择渠道、首次渠道向导计时、拖动浮窗和跟随聊天 DOM 的样式分别由现有渠道设置、预设选择、桌面面板和手机抽屉承接。第三方扩展的消息强制后处理、日志上传、工具绑定及独立变量缺乏王朝业务权限，内置包不包含这些扩展。

方案 JSON 沿用 `wave-console-scheme` v1 的家族标识。导入时检查格式、重复条目和字段类型，在预览后才将可编辑文学项目载入编辑区，玩家保存后才影响生成。方案及外观按浏览器保存，1124 的文学覆盖按预设 ID 与版本保存。人物、场景、时钟与历史始终读取当前存档。切离 1124 时第三份脚本随宿主卸载。

常规回合中每次 Mock 收到 1 份 POST。空行动开局正常交付当前人物及世界资料，16 个用例均保存了正文候选。过滤结束和半截 SSE 均维持正式 revision 1，草稿的正文 revision 仍为 0。两个控制台用例验证编辑、估算与时序核对期间共 0 份 POST，保存后的采样和文学编辑进入下一次真实序列化请求。[开局记录](opening.json) · [原始测试输出](checks.log.gz)

**已知边界**　既有 HTTPS 用例在复用 HTTP/1.1 直连、模型已收件后断开时，桌面和手机模拟均观察到应用直连 1 次、Worker 0 次、模型端收件 2 份。正式回合和草稿保持原值。这是 #247 已记录的 Chromium 网络层重发，严格收件断言保留。未测试真实供应商、实体手机和实模文学效果。[#247 的传输证据与复现说明](../LITERARY_OWNERSHIP.md)

开发中一次 54 项运行遇到重建 dist 期间的页面 404，两项手机开局用例未能加载页面。固定构建完成后重新运行全部 54 项，全部通过。另一次开发服务器热刷新中断了一次既有直连用例的页面加载；单独复跑传输套件时，直连成功用例在两端均通过。此处不将多次运行相加。最终提交和对应 Actions 链接记录在本专项 Draft PR。
