# 黑金王朝 V0.1｜游戏设计规范

**文件性质：** V0.1 Alpha 正式开发基线 · 游戏体验与功能需求  
**版本：** 0.1.0-design · 2026-10-18  
**配套文件：**《黑金王朝 V0.1｜技术开发与实施计划》  
**参考：** 已完成的《黑金王朝 V1.0 整体架构与功能设计（讨论稿）》及后续逐项讨论；《墨色江湖》仅作架构参考。

> **阅读约定**：标注【确认】的条款是目前已经讨论确定的需求；【建议】是便于开发的实施主张，Codex 可在不改变用户体验与数据安全要求的前提下提出调整；【待实测】为需通过原型验证的参数与交互。本文所谓“V0.1”是**游戏版本**，不是旧讨论稿的“文档 V1.0”。

## 01｜项目定位与首发边界

### 1.1 一句话定义【确认】

《黑金王朝》是一款以当代中国现实城市为舞台、由 AI 推动叙事与动态世界的自由文字开放世界游戏。玩家从普通人的生活遭遇一场严重、可信且带有不公意味的重大变故开始，可以自行选择复仇、维权、创业、远走他乡、回归普通生活等人生道路。**起点有冲突，人生不预设结局。**

### 1.2 游戏体验原则【确认】

- **玩家主导行动**：AI 描写世界反馈，不擅自替玩家表态、承诺、交易或决定未来；防抢话开关用于进一步强化文风边界，不取代基础玩家控制权。
- **现实社会运行**：采用真实中国城市与生活逻辑；组织、案件、人物可以虚构，机关权限、交通、消费、行业常识须有现实约束。
- **世界在场外运转**：NPC、公司、组织拥有目标与合理耗时；不是每回合都必须出现冲突或重大消息。
- **不采用传统 RPG 面板**：不建立力量、魅力、智力等数值属性，也不设置升级经验；能力由职业、经历和自然语言技能定义。
- **后果可追踪**：金钱、人物关系、物品归属、时间、任务及事件状态有统一真实数据来源，不允许“正文说买了车，资产里没车”。
- **适合长期游玩**：记忆分层压缩，原文永久归档，重要历史可回看，存档与回退可靠。

### 1.3 地理与开局范围【确认】

初始可选城市为**重庆、上海、哈尔滨、广州**四地。开始游戏之后允许前往其他现实存在的城市，不将世界锁在四座城市。地点采用可扩展层级，例如“中国 → 重庆市 → 渝中区 → 街道／建筑”。不要求在 V0.1 制作全国完整建筑数据库。

### 1.4 V0.1 不做什么【确认】

暂不开发世界书／Lorebook 自由配置器、玩家自定义世界与自由变量 Schema、独立 NPC 长篇叙事的额外 AI 环节、复杂 RPG 数值成长、完整经营模拟后台、多人在线、全面世界百科。完整《浮生境》通用引擎能力留待后续迭代。开发顺序以**先能玩、再扩展**为原则。

## 02｜玩家进入游戏的完整路径

新建游戏 → 五步角色创建 → 开局专用三阶段生成 → 查看开局正文和主角状态 → 玩家自由输入行动 → 普通回合三阶段执行 → 查看变更、存档与历史 → 持续游玩。

生成正文可以反复 Roll；正文满意后再启动或补算变量管理及动态世界。查看 NPC、物品、记忆、地图和时间轴不应打断正在运行的生成任务。

## 03｜五步角色创建【确认】

| 步骤 | 页面 | 主要内容 | 交互原则 |
|---|---|---|---|
| ① | 基本信息 | 姓名、年龄、性别、外貌、性格 | 自由输入，不放长篇个人背景 |
| ② | 职业与能力 | 16 种预设职业或自定义职业；职业介绍与能力特长说明 | 选择后仍能修改技能／专长 |
| ③ | 城市与背景 | 上方约 2/3 介绍并选择城市；下方约 1/3 可选自由人物背景 | 先了解职业与城市，再决定写不写背景 |
| ④ | 初始同伴 | 可选，自行创建一名重要特殊 NPC | 可跳过；玩家自定义关系和背景 |
| ⑤ | 确认与开局 | 完整汇总，返回编辑，可写开局偏好、生成或重新 Roll | 所有已填资料保持不丢失 |

### 3.1 角色基础信息

外貌、性格以自然语言表达，不强制从固定标签选择。婚姻、子女、任职机构、毕业经历、个人秘密等不新增一排必填问卷，而是在第三步“人物背景”中自由描写。

### 3.2 第三步：城市介绍与背景【确认】

上方主要空间展示四座城市及对应介绍。城市选择决定开局地理、生活习惯、出行和当地社会氛围，不作为职业限制。下方明确提供“自行填写角色背景／跳过”选项；自由背景可写任教学科、婚姻关系、家庭成员、个人经历等。未填写时 AI 可以合理补充，**已经填写的事实不能被擅自覆盖**。已经写过的文本在切换城市、返回步骤后仍应保留，出现明显冲突时在确认页提示而非悄悄改写。

### 3.3 16 种预设职业【确认】

每张职业卡片提供**职业介绍**与**能力及特长介绍**两个清楚区分的段落；完整文案可在前端作为静态配置管理。选择职业之后允许编辑或补充个人能力；最后额外提供“自定义职业”。

| 职业 | 职业介绍 | 能力与特长介绍 |
|---|---|---|
| 大学生 | 在高校学习，尚未完全进入职场，日常与校园、专业学习及社交有关。 | 具有所学专业的基础知识、学习能力与校园生活经验。 |
| 教师 | 从事学校教育工作，与学生、家长、同事及学校制度长期接触。 | 擅长讲授、沟通、教学组织与专业学科知识。 |
| 医生 | 在医疗机构承担专业诊疗职责，受资质、岗位与医院流程约束。 | 掌握对应专业的医学知识、伤情判断及相关急救经验。 |
| 律师 | 处理民事、商业或刑事法律事务，熟悉委托、文书与司法流程。 | 具备法律检索、证据整理、谈判和法律程序知识。 |
| 刑警 | 公安机关刑事侦查岗位，职责和可用资源受制度与权限约束。 | 具有侦查、调查取证、现场观察及警务协作经验。 |
| 记者 | 从事新闻采访、调查和报道，接触多种社会群体。 | 善于采访、核实材料、发现线索和文字表达。 |
| 程序员 | 在数字技术行业从事软件开发、维护或相关技术工作。 | 具有编程、系统分析与技术排障技能，方向可自定义。 |
| 企业职员 | 在企业中承担具体业务职能，熟悉职场与公司协作。 | 具有与岗位相关的办公、沟通、业务及专业能力。 |
| 企业经营者 | 经营企业或负责管理事务，面对市场、资金与团队压力。 | 熟悉经营、谈判、管理和行业资源整合，但不保证富有。 |
| 个体商户 | 经营小型门店或个人生意，与顾客、供应商及社区密切来往。 | 擅长日常经营、定价、采购、沟通及本地商业判断。 |
| 外卖骑手 | 在城市中从事即时配送，熟悉大量街区与日常民生场景。 | 熟悉路线、小区、商圈与配送调度，有实际街面经验。 |
| 网约车司机 | 从事城市客运服务，日常接触不同乘客与道路环境。 | 驾驶熟练，熟悉道路和城区分布，具有服务与沟通经验。 |
| 汽修技师 | 长期处理机动车维修与保养相关的技术工作。 | 熟悉车辆机械结构、故障排查和常用维修工具。 |
| 安保人员 | 在企业、场所或机构执行日常安保及出入管理。 | 熟悉秩序维护、风险观察及与岗位匹配的应急程序。 |
| 基层公务员 | 从事基层公共服务或行政工作，岗位受到法律与制度限制。 | 了解行政流程、政策文件、公文和部门协作。 |
| 自由职业者 | 以非固定雇佣方式提供服务或独立工作，经历较灵活。 | 专长随个人业务而定，具备自我安排工作和客户沟通经验。 |

### 3.4 初始同伴【确认】

同伴由玩家选择是否创建，属于**特殊 NPC**。建议输入姓名、年龄、身份、外貌、性格、能力、个人经历、与主角的关系。开局专用提示词保证其在开局重大变故中**不死亡、不背叛、不无故怀疑主角**；这条保护**仅在开局生效**，后续正常游戏允许关系因有充分铺垫的经历发生变化。背景里提到的家人不等于全部自动成为受保护的初始同伴。

## 04｜开局与普通回合：两套提示词【确认】

游戏固定三个 AI 工作环节：**① 正文生成 → ② 变量管理 → ③ 动态世界**。但“创建游戏的第一回合”与“后续普通回合”必须各自有专用主提示词，形成六组互不混用的工作流提示词。

| 阶段 | 开局专用行为 | 普通回合行为 |
|---|---|---|
| ① 正文 | 基于职业、城市、背景与同伴产生严重、可信的不公变故；不预设后续道路 | 自然承接玩家行动、状态、记忆与事件，描写因果反应 |
| ② 变量 | 建立初始主角、相关重要 NPC、基础资产物品、时间地点 | 核对正文并更新已有变量、建档或修改实际在场的重要 NPC |
| ③ 动态世界 | 初始化相关势力、场外 NPC、未来计划和重要事件 | 追踪与推进场外行动、组织事务、事件到期和结算 |

共享世界观、信息隔离、变量组 Schema 与基础输出协议，但开局专属限制绝不泄漏到普通回合。开局故事不等于剥夺所有预设资产或强制全员死亡；“人生崩盘”需要与玩家选择的人生合理关联，且保留角色后续自由选择。

## 05｜正文叙事与玩家交互【确认】

### 5.1 正文阶段的四种结果

1. **叙事正文**：让玩家阅读的主要小说内容，允许流式展示。
2. **本回合短期记忆**：记录关键既成事实、变化和未了线索，不替代正文。
3. **变量规划／变量指导**：用自然语言告诉第二阶段本回合可能应更新哪些变量及事实依据；**不是可执行更新命令**。
4. **行动选项**：开关开启时生成 3～5 条建议。点击将文本带入输入框，不直接执行。

### 5.2 叙事边界

允许描述意外、失败与 NPC 主动反应，不保证主角每次行动都成功；但不能替玩家作重要抉择。对话、物理移动、交易、时间变化需要有可理解的经过。现实世界模式打开时进一步强调合理制度、技术、社会和行动时间约束。

### 5.3 自由 Roll 与双开关【确认】

变量管理、动态世界各自拥有**独立启用／关闭开关**，且在输入框附近能便捷操作。玩家可以反复重新生成当前正文，并保留自己满意的一版。关闭模块不应偷偷扣款、建档或推进场外事件；正文定稿后可以直接对该版本补运行后续阶段，无须强迫重写正文。

**与普通已结算回合的区别**：只写了正文但还没同步变量的回合属于“草稿／待同步”，页面需明确提醒“世界状态尚未确认”。关闭某一模块是用户意图，不是 AI 失败。进一步关于多回合长期保持草稿模式的处理，以技术文档的保守方案为开发基线并列为测试点。

## 06｜六大变量组【确认】

| 变量组 | 核心范围 | 特殊要求 |
|---|---|---|
| 主角 | 基本身份、背景、职业、文字技能、身体与精神状态、社会／法律处境、当前位置、当前穿戴与装备引用 | 不使用力量等 RPG 数值属性 |
| 普通 NPC | 身份、性格、与主角关系、好感度（−100～+100）、记忆、地点、当前状态 | 仅有持续关系潜力时建档，不建立路人普查库 |
| 特殊 NPC | 更细致的人生经历、习惯、私人记忆、关系、目标和独立计划 | 初始同伴固定特殊 NPC；有独立后台行动 |
| 重要物品 | 唯一 ID、类别、数量、状态、归属、位置、必要的类别专属信息 | 日常一次性小物不强制追踪；与装备栏共享物品真值 |
| 经济与资产 | 现金、线上资金、收入、债务、房产、车辆、其他资产 | 大类显示简洁，明细无限扩展，账目不重复计算 |
| 势力与组织 | 黑帮、官方、民间组织、商业集团四组专属 Schema | 全部具备开放文字的“与主角关系”及其缘由 |

### 6.1 主角

常显身份、职业、身体／情绪、现金与线上资金。外貌、性格、技能、背景、法律身份等可看详细档案。**穿戴、主武器、副武器、饰品、当前载具**显示的是“当前使用／装备状态”；未持有或未装备显示“无”，绝不默认主角持武器。

### 6.2 NPC

普通与特殊 NPC 分开管理。在场互动涉及的 NPC 由变量阶段筛选建档；场外 NPC 的已有档案与行动由动态世界负责更新。好感度范围为 −100 到 +100，只表示综合关系倾向，**不等于恋爱进度**；亲情、信任、畏惧、仇恨均须用文字解释，重大变化需符合已有经历。不为一次问路就默认生成永久角色档案。

### 6.3 物品、装备与车辆

物品实体的来源、数量和归属应唯一。服装／武器／饰品属于已拥有物品中的“当前穿戴或装备引用”。车辆属于经济资产，有当前使用载具的引用；不再在重要物品栏复制一辆资产车。装备调整不得凭空生成新物品、双重持有或错误改变数量。

### 6.4 经济与资产

七个外层分类：**现金、线上资金、收入、债务、房产、车辆、其他资产**。现金和线上资金分别表示不同持有形态，电子资产采用统一可用余额，避免银行卡与支付平台同笔钱重复求和。收入／债务／资产分别拥有独立条目、来源和状态。工资发放、债务到期、房贷扣款等要先通过情节或已有自动扣款约定成立，再由变量管理落库，不能无故自动转钱。

### 6.5 四类组织各自有独立字段

| 类别 | 特有重点 |
|---|---|
| 黑帮势力 | 地盘、经营来源、组织资金、综合实力、内部稳定性、与外部势力的利益关系 |
| 官方势力 | 法定职权、管辖范围、案件与事务、执法能力、公众信任、内部情况；不强制有“资金／繁荣度”游戏化数值 |
| 民间组织 | 宗旨、成员和支持者、活动范围、社会影响、服务行动 |
| 资产阶级／商业集团 | 产业、资产与可用资金、股权控制、经营情况、商业关系 |

每类组织都保存**与主角的关系（开放文字）**与形成原因，允许诸如“素不相识”“深仇血恨”“局部渗透”“附属组织”“受到重点调查”等复杂状态；不限制在“友好／敌对／中立”三档。不同机关、部门、组织的影响范围必须现实可信，不能因为玩家影响一个人便自动控制整座城市。

## 07｜时间、天气与动态事件【确认】

### 7.1 唯一游戏时间

游戏采用独立于现实时间的世界时钟。时间推进取决于真实行动耗时；不可每回合机械加固定分钟。变量阶段确认最终时间，动态世界据此推进离场行动。每个可追踪事件至少标注开始时间、状态和预计完成时间或条件。

### 7.2 合理中断长时间跳跃：采用方案 A

例如上午 8:00 玩家打算睡到晚上 20:00，而 15:00 有重要人物上门。程序在正文前检查已安排事件，判断它是否可能触及当前场景；只有真能通过敲门、电话、事故等合理渠道影响主角，才可能中断跳跃。是否叫醒主角取决于实际情节，不强制每次打断；与主角无关的外地会议不会打断睡眠。长时间跨越需要结算期间所有关键时间节点，避免漏执行与重复执行。

### 7.3 场外行动

NPC 和势力组织可以按自身目标行动，并具备地点、耗时、任务状态和阻碍条件。动态世界可以保持平静，不为输出而强行安排冲突或每回合势力交锋。场外秘密不会无故成为主角已知事实；必须有合理传播途径。

### 7.4 天气与环境

左栏顶部显示游戏时间、当前地点、天气和**环境描述**。天气作为游戏世界的连续状态，可随季节、时间和地区变化；V0.1 无须实时天气 API。环境描述简要呈现附近氛围，只有场景明显变化时才重写，不额外透露隐藏情报。

## 08｜记忆与历史档案【确认】

### 8.1 分层记忆

即时记忆默认向正文模型注入最近 **10 回合完整剧情**，玩家可在“记忆与上下文”设置中自由修改数字。较久远的回合按《墨色江湖》成熟机制生成短期、中期、长期摘要，NPC 具有独立记忆和压缩。**读取窗口变小不等于删除原文**，所有已保存回合的原文与摘要保留在历史回忆档案中。

现有参考研究曾记录《墨色江湖》短期 30 条、中期 50 条、NPC 总结 20 条等默认阈值；具体批次、保留条数及生效规则**实施时以源项目对应版本源码复核为准**，不由 UI 再创造一组新参数。

### 8.2 历史回忆检索

允许按需检索旧回合，在正文需要时重新装入相关原文或摘要。V0.1 先优先采用本地索引与关键词匹配，无须强制新增回忆 AI 调用。重要事实（婚姻、债务、预约、人物死亡等）还应在相应结构化数据中保存，不仅依靠摘要。

### 8.3 玩家可查看的记忆界面

右栏“记忆”一键打开独立界面，能够查看即时、短期、中期、长期记忆及其来源；不在狭窄右栏内直接展开大段记录。NPC 的私有未公开情报不能通过普通玩家记忆界面泄露。

### 8.4 独有设计：重要事件历史时间轴

世界事件系统记录未开始、进行中、已结算的事件；**历史时间轴只收录影响较大、已经完结且玩家合理获知的事件**。按**事件在游戏世界实际发生或结案的日期**排列，展示标题、时间、地点、简述、结局、影响、主要关联人物／势力、对应原文回合。日常吃饭、普通小交易、闲聊不收录。重大但主角暂未知晓的事件可在内部记录，知晓后再按真实日期归位。没有 NPC 全知权限。

## 09｜游戏主界面与独立面板【确认】

### 9.1 三栏总体结构

**左栏看主角，中间玩剧情，右栏一键进入世界资料。** 三栏独立滚动／阅读，优先保证中央长文本的阅读宽度。具体颜色、字号和占比允许在视觉原型阶段调整。

### 9.2 左栏：可上下独立滚动

从上至下为：① 当前日期时间；② 当前地点；③ 天气；④ 简短环境描述；⑤ 主角姓名年龄职业及健康／情绪；⑥ 现金与线上资金；⑦ 当前服装（上衣／下装／鞋／饰品）；⑧ 当前主武器、副武器与载具（允许“无”）；⑨ 技能、详细档案、资产、收入债务等进一步入口。左侧展示“当前装备和使用状态”，不是完整背包。

### 9.3 中栏：剧情与运行反馈

包含已生成的剧情、当前正文、可选 3～5 个行动建议、玩家文本输入、发送／重新 Roll 操作和“继续推演”。**输入框上方**安放 AI 工作流流式运行面板：正文、变量、世界三个阶段的状态、当前尝试次数、失败后“重新加载”按钮及变量变更详情。变更详情应可查看前值 → 后值、建档或归属变化；生成中显示“预览”，完成事务后才标记“已生效”。

### 9.4 右栏：纵向一列的直接入口

右栏始终能直接看见七个入口：**NPC、势力组织、地图、物品栏、世界事件、历史时间轴、记忆**。**点击一次即打开宽敞的独立界面／覆盖层**，不能先切换标签再进入，也不能把大量内容作为手风琴直接挤在右侧。关闭独立界面返回原来的正文阅读位置。打开资料时已有 AI 流式任务不丢失。

### 9.5 特定界面功能边界

- **物品栏**：展示已拥有的重要物品、数量、位置、类别属性；与左栏当前装备引用同步。
- **世界事件**：呈现主角可知晓的、仍在进行中的重要事件及进展；隐藏的场外计划不剧透。
- **历史时间轴**：只展示已结算的重大历史节点，可回看对应回合。
- **地图**：可扩展的中国现实地理层级；不要求首版完成全国精密街道制图。
- **NPC／势力**：有搜索与详情，保留普通／特殊 NPC 与四类组织的区分。
- **设置**：独立入口，与右栏游戏变量面板分开；**开发者公告栏**是游戏版本公告，不属于剧情世界内通信。

## 10｜设置界面【确认，个别默认值待实测】

### 10.1 四个类别

| 类别 | 控制范围 |
|---|---|
| AI 连接 | 保存多个 API 渠道、协议与密钥、手动模型 ID／模型列表、连接测试、模型路由与生成参数 |
| 提示词 | **严格七项**叙事与协议选项，不混入程序参数 |
| 记忆 | 即时记忆完整读取回合数，默认 10；摘要阈值不必暴露 |
| 运行 | 变量管理、动态世界两个独立开关；请求超时、结构校验及失败恢复等 |

### 10.2 三阶段模型分别配置

正文、变量管理、动态世界可以使用不同 API 渠道和不同模型；后两者也能选“跟随正文”。渠道地址与密钥只需登记一次。记忆总结等辅助任务 V0.1 可默认继承主模型。高级输出参数默认隐藏。模型切换不清空存档；密钥不写入可分享的游戏存档导出文件。

### 10.3 严格七项提示词设置

| 设置 | 控制形式 | 初始值／状态 |
|---|---|---|
| 叙事人称 | 第一／第二／第三人称三选一 | 建议第三人称 |
| 剧情风格 | 风格提示词互斥选择 | “一般”已明确；更多预设文案待补 |
| 正文最低字数 | 自由填写**硬性最小值** | 建议 1500；仅统计正文 |
| 防抢话 NoControl | 开／关 | 建议开启 |
| 自然文风修复 | 开／关 | 建议开启，参考用户已验证规则 |
| 行动选项 | 开／关 | 建议开启；开启时 3～5 条 |
| 真实世界模式协议 | 开／关 | 建议开启 |

不额外塞入剧情节奏、NoControl 强度、自然文风强度等未约定设置。任何强制字数检测必须与选项、记忆、变量规划的文本分离。

### 10.4 运行开关与重试

**变量管理与动态世界都允许单独关闭**，方便玩家反复 Roll 正文。两者默认开启【建议】。开启时正常运行；关闭时不生成该阶段的持久副作用。AI 请求失败采用**首次 + 自动重试 2 次，共 3 次**；若变量三次失败，继续运行仍可运行的动态世界（结果为待校验）；末尾显示手动“重新加载变量”。动态世界三次失败同理提供独立手动重新加载。正文或其结果不因此消失。

## 11｜存档、回退与透明度【确认】

支持多个游戏存档，逐回合原文永久留存，完整回合能够回退并恢复同一时间点的金钱、NPC、物品、势力任务、未来事件与历史时间轴。重新生成正文会舍弃该版本后续草稿效果；“重新加载失败阶段”则只重跑失败的那一阶段。**同一笔收入、同一辆车、同一条事件只能结算一次**。

所有阶段均可流式显示。不同状态必须清楚标识“已生成（预览）”“待校验”“已确认生效”“失败，允许重试”。开发调试信息可以详细，但普通玩家界面不得泄露尚未被主角获知的秘密计划。

## 12｜验收标准与版本外功能

### 12.1 首版玩家可感知的最低验收

| 场景 | 应有表现 |
|---|---|
| 四城＋任意职业开局 | 开局生成贴合背景的重大变故；无需固定剧本；伙伴开局保护生效 |
| 连续普通日常 | 不强制黑帮冲突，不会随机吞掉金钱、物品或 NPC 状态 |
| 一次购车、收工资、转账 | 正文有明确事实，变量更新准确，重复加载不二次扣款 |
| 重要 NPC 离场再回归 | 角色记得关键经历，后台行动与时间一致 |
| 睡过一个有预约的下午 | 可合理中断或错过约定，不漏掉下午事件且不全知 |
| 多次 Roll 同一正文 | 仅最终选定的一版参与结算；其他尝试无永久副作用 |
| 阶段连续失败三次 | 正文保留，阶段显示失败并可独立手动重新加载 |
| 关闭变量／世界开关 | 未开启阶段不产生对应副作用，正文可继续修改／补算 |
| 历史时间轴 | 重大结案入列，吃饭闲聊不入列，秘密事件不剧透 |
| 100 回合回归测试 | 无反复重大状态错乱、重复扣款、时序倒退或归档复制 |

### 12.2 后续版本与开放问题

【待实测】剧情风格候选文案、正文默认字数、具体 NPC 记忆阈值与压缩批次、极长时间跳跃时事件切片上限、窗口布局细节、长期关闭变量更新时的体验，以及 API 供应商兼容覆盖。以上不得擅自扩成新的 V0.1 玩家设置。

**设计冻结原则**：先按本稿与配套技术文档交付可玩 V0.1；发现实际矛盾时先记录并提出最小修订，而不是随意新增整套系统。
