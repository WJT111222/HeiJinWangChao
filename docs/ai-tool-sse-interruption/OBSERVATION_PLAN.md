# SSE 首帧前中断的最小观察方案

范围为已存在的 Story Tool Call 临时诊断。公开错误、SSE 解析、结束事件、取消、请求次数、总时限、业务校验及保存行为均维持原有规则。此文档仅供审查。

## 建议数据

| 字段 | 投影 |
| --- | --- |
| `contentType` | `event_stream`、`json`、`other_json`、`html`、`text`、`missing` 或 `other`。从媒体类型分类，丢弃原始头和所有参数，分类结果不参与传输路由。 |
| `firstReadHadBytes` | 第一条非 EOF 的读结果是否有字节。尚未得到读结果时为空；现有 `firstBodyChunkMs` 仍是首个非空块事件。 |
| `reads`、`nonEmptyReads`、`bytes` | 读结果与字节计数，排除 EOF，分别饱和在建议上限 2³¹−1。通过布尔标记告知该计数是否饱和。 |
| `dataLines`、`commentLines`、`blankLines` | 复用现有扫描分支产生的计数。只将实际识别为注释语法的行计入注释，不推测心跳来源。 |
| `delimitedDataEvents`、`eofDataEvents` | 分别统计经空行交出和现有 EOF 尾部兼容分支交出的实际数据事件。单独收到空行不代表完整数据事件。 |
| `readerEof`、`bufferedTail`、`pendingData` | 已观察到未取消的 reader `done=true`；终止时文本缓冲和完整待交出的 data 行是否存在。仅布尔值，不能从无残尾推断解码器内部没有残留字节。 |
| `sseFailureSite` | `missing_body`、`reader_read`、`utf8_chunk`、`utf8_eof`、`unrecognized_eof_tail` 或空。只在对应真实分支采样。取消和总超时保持现有结局，取消导致 reader 返回 done 不认作正常 EOF。 |

`readerEof=true` 且高层 `boundary=null` 可以明确解释为已观察 EOF 但未向上层交出结束事件。枚举证据描述程序发生的位置；例如 `reader_read` 无法区分服务器、代理、浏览器网络栈或本地连接的具体来源。超出 SSE 读取范围的同名错误继续依靠现有客户端阶段和事件证据，无需把它们归入 SSE 枚举。

## 接入点与隐私

1. `responseEvents.ts` 在现有响应到达及缺 body 位置投影媒体类型和固定枚举，沿可选 Story Tool 观察器传入 `readSse()`，不更改传输选择表达式。
2. `sse.ts` 使用现有的单一 reader、解码和行扫描。读取失败、块解码失败、EOF 解码失败各自在原调用点采样并重新抛出，既有外层错误处理继续负责映射。EOF 残尾拒绝前仅标记枚举。计数在已有分支上更新，不重复扫描、保存或复制字节，不增加异步等待。
3. `storyToolTrace.ts` 持有固定大小的数字与布尔状态，沿现有安全观察、封存和导出流程投影。诊断关闭时不采样；采样出错不得影响结果。继续用原请求观察记录的生命周期和归属。导出沿用原 PC／手机入口，默认不展示，不新增普通运行日志或数据库写入。
4. 投影字段只接受固定枚举、有限计数和布尔值。禁止存入原始字节、原始头及其参数、接口 URL、错误异常字符串、正文、思考、参数、密钥和真实存档标识。观察器更新不复制响应，不挂接第二个 reader，不复读 JSON。

## 实施验收

在现有隔离夹具上先增加对拟议枚举及 EOF 状态的断言，证明原导出缺少鉴别能力，再实施观察补丁。用相同输入对照开启、关闭和观察器异常，要求请求字节、调用次数、失败类型、取消信号和 Repository 结果一致。补测首个空块、计数饱和、错误 MIME 及其自定义参数、读取取消竞态、EOF UTF-8 flush、正常 DONE、正常 EOF、导出脱敏以及取消后迟到输出。观测通过后才采集自然失败的主动导出，若仍不能归因，再评估是否需要经预算批准的真实调用。任何解析策略变化单独审查。
