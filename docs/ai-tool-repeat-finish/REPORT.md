# PR #191 · OpenAI 兼容 SSE 重复结束返修

本轮基于 PR #191 的 `1b81aef2e9750dcf153f30a1b5f817d11d91d4b5`，main 为 `a820f5eadcd18362aa22a2fc51232a186e2ef8f9`。

玩家提供的脱敏轨迹摘要显示，第三方中转以 HTTP 200 返回 SSE。第 16 帧第一次报 `tool_calls`，同帧含合法名称、非空参数和派生的工具结束。第 18 帧第二次报 `tool_calls`，触发 `tool_response / storyTool.ordering / duplicate_provider_finish`。请求用时 91,554 ms，报错时尚未读到 `[DONE]` 或 EOF。不能从这一点推断后续有没有真正的结束边界。测试只使用上述已知信息合成帧，第 17 帧用独立 usage 作为占位，其他前缀、响应标识、文本和参数全部为虚构。仓库未收录玩家原始文件。

`readAiResponseEvents` 先返回该帧的结束原因，再投影同帧的工具事件。装配器允许首次 finish 与同帧工具参数和工具结束配合。此前遇到第二个 finish 时，哪怕它没有增量，装配器也会无条件中止，因此消费者尚未到达实际传输结束。

返修只允许 **OpenAI 兼容的 Story 工具 SSE** 容忍后一帧的 `tool_calls`。要求首次 finish 已出现、唯一工具调用已关闭，尾帧只能属于选择 0，且只携带空增量和允许的结束元数据。可接受的空增量为省略、空对象，或已知正文、推理、拒绝字段的 null／空字符串占位。若尾帧再次提供响应 ID 等信封字段，值须与首次 finish 一致。夹带 usage、新工具参数、调用、推理、文本、选择字段或其他内容的帧仍拒绝。独立的纯 usage 帧仍按原逻辑消费。明确的 SSE `error` 事件即使数据碰巧是 `[DONE]`，也不能成为成功边界。

尾帧只增加脱敏诊断中的 `tolerated-provider-finish` 事件及计数。原来的两个 `provider-finish` 仍在轨迹中，首个结束位置、工具结束次数和传输边界由实际事件决定。事件只含固定类型、帧号和时间，信封值不会进入该诊断。出现实际 `[DONE]` 或干净 EOF 之后，仍需通过完整工具参数 JSON、Story 校验及现有草稿 CAS。打开但没有结束的连接仍可取消，仍受原 120 秒总超时约束。
