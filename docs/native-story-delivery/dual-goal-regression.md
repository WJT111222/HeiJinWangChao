# PR #215 玩家行动与长正文工具交付对照

在同一份合成开局、同一条仓库询货行动上，四种协议都复现了一处客户端回归。上游先发一个只含空格、换行和制表符的 SSE 文本帧，再交付完整的 `actual_content.content`。真实浪潮脚本已经向下游转发了前面的空白。旧版保存了完整正文，上一轮返修把这份回包判为交付不匹配。本次修正了这条误拒路径。玩家报告的 Build 退化缺少对应的上游响应结构，尚无法确定是否命中了同一分支。

## 最终出站请求

对照使用旧版 `e593dcbc72cd82065fd2536beefed60e9ac3326c`、上轮 `2e6e6bc4e507280ced9e68b423cf10a93873266c` 和本次候选。main 基线为 `daf32fe7e12f4d5af1f6b2120dc2363f133adaa2`。在三个生产构建上分别启动正式游戏和内置主脚本，Chromium 在 Mock 上游的 HTTP 边界捕获 JSON。下表为 OpenAI 兼容、非流式样本，字节数按 UTF-8 计。

|---|---:|---:|---:|
| system / user / assistant 消息数 | 24 / 3 / 1 | 24 / 4 / 1 | 24 / 3 / 1 |

普通消息的估算按换行连接内容后使用项目的 `unicode-heuristic-v1`；未取得真实供应商 usage。四协议、两种传输都逐字段比较了最终请求。旧版至上轮只涉及消息和资料工具说明，上轮至本次只涉及普通消息数组。两份工具 schema、输出工具说明、模型选择、温度 0.25、最大输出 8192 和推理配置一致。OpenAI 兼容与 DeepSeek 保留 `tool_choice: "auto"`，Gemini 保留 `AUTO`，Anthropic 保留 `{type:"auto"}`。

把普通消息和资料工具中的结构化上下文按原键合并，三版的字段和值相同。本次普通消息直接提供 `SAVE_STATE`、开局档案、时间、事件、人物知识规则、近期剧情和记忆摘要；`wave_context_reference` 仍搬运 NPC 索引和额外历史召回。当前草稿行动只在普通用户消息中出现一次。普通回合测试另行核对近期历史；时间预检的 `actionKind` 只说明时间安排。

`finalizeNativeDelivery()` 在脚本准备好两个工具后核对冻结行动，把行动与脚本实际追加的交付说明放入同一条末尾用户消息。它把读资料提示中指向“其中最新的真实用户输入”的短语改为指向本消息的 `PLAYER_ACTION`。原脚本要求调用 `actual_content` 的交付段全文仍在末尾，原生系统模块、格式提醒和文学预设互斥规则均沿用上轮。这个次序变化可以在 HTTP 上验证；它对真实模型调用意愿的影响需要另行测量。

## 响应、保存与失败

以下计数表示浏览器实际读回的 Story 候选。每行每版 8 次，分别为四协议的 JSON、SSE；提前 EOF 行仅测四种 SSE。每次操作只有一次 Mock 上游传输。

| 合成上游交付 | 旧版保存 | 上轮保存 | 本次保存 |
|---|---:|---:|---:|
| 正确工具，11,845 字符正文 | 8 | 8 | 8 |
| 同一正确工具，另有前导空白文本 | 8 | 4（仅 JSON） | 8 |
| 只给符合格式、回应行动的普通正文 | 8 | 0 | 0 |
| 只给文本标记，当前请求约定工具交付 | 0 | 0 | 0 |
| 把正文交给资料工具 | 4 | 0 | 0 |
| 正确工具只返回未声明的 `text` 参数 | 8 | 0 | 0 |
| 任意其他工具 / 损坏参数 / 上游限制 / 供应商错误 | 各 0 | 各 0 | 各 0 |
| 提前 EOF，未取得有效结束 | 0 | 0 | 0 |
| 正确工具，但给出语义无关、结构合法的故事 | 8 | 8 | 8 |

长正文通过真实内置脚本还原后，与送入工具的预期剧情逐字符相等。OpenAI 兼容、DeepSeek 和 Anthropic SSE 每片至多 127 个码点；Gemini SSE 使用现有协议支持的完整函数参数快照。输出预算不足时四协议均未保存该批工具结果。该场景的 Gemini `MAX_TOKENS` 在三版均报告 `invalid_output`，其余协议报告 `output_limit`。

`Frames` 仅在需要验证原生工具的 SSE 请求中统计工具出现前的 JSON 空白。通过已有的工具名称、单调用、身份、参数完整性和结束检查后，除既有匹配方式外，允许还原结果在完整工具原文前多出等长的 ASCII 空白。参数内部、尾部和任意可见文字仍受原匹配约束。缺失工具、工具名错误或只有普通文本时没有可验证的交付；重生成失败保留已有合法候选和正式 revision。结构正确而语义跑题的反例仍会通过，工具身份无法证明模型理解或执行了行动。

## 复验

- `src/tests/tavern-backend.test.ts` 新增前导空白、额外文字、不可见非 JSON 空白、内部文字变更、尾部变化和无上游前缀的对照。上轮定向运行中新断言失败。
- `e2e/peinture-settings.spec.ts` 通过真实设置启用脚本，在四协议 JSON/SSE 上直接检查出站行动、指令顺序、两份声明、Mock 次数和 IndexedDB 中的长正文。上轮生产构建的末条用户消息没有原交付指令，桌面断言失败。
- `e2e/tavern-assistant.spec.ts` 和 `e2e/tavern-backend.spec.ts` 覆盖普通回合重生成失败、取消、旧候选、正式 revision 与其他三个阶段出站请求。在独立传输对照中另测了四协议的 8 次主动取消和 4 次 SSE 读取异常；均为单请求，未保存候选。

Node 24.19.0 下完整检查通过，197 个测试文件、4,772 项 Vitest 全部通过，ESLint、TypeScript、生产构建通过。另跑定向 Vitest 339 项、Prompt 93 项，两者与全量有重叠。Chromium 154 的生产构建定向用例 36 项通过（桌面、手机模拟各 18），宿主与后端用例 18 项通过（各 9）。生产套件首次与宿主套件并行启动时占用同一端口，在执行用例前退出，随后单独完整运行。三版隔离矩阵各独立完成 92 次；候选矩阵首次并行启动页面时超出夹具等待时间，重新等待游戏首页就绪后全批复跑，统计只取完整批次。

## Build 实测仍缺的证据

优先核对已有失败请求的脱敏记录。需要同一次尝试的出站工具名和选择、上游实际回包形式、工具名和参数形状、是否先有普通文本、真实 finish、还原状态、错误字段和候选保存结果。这样可以区分模型没调工具、中转返回普通文本、传输截断以及完整工具结果被客户端拒绝。无须提供剧情原文、工具参数内容、密钥或完整接口地址。

若历史记录不足，待负责人另行批准后，可在隔离副本上用旧版和本次候选各生成一次。固定存档、回合、行动、渠道、模型、采样、流式、预算与篇幅，记录上述指标以及实际 usage。单对样本只能验证该次走了哪条交付路径；成功率需要多次独立样本。本轮所有传输均为 Mock。
