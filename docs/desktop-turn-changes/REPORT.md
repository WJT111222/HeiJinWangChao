## 恢复点可靠性与存储边界

新增 `SaveRepository.turnComparison(expected)`，在一个 IndexedDB **readonly** 事务中读取 saves、drafts、saveControls、turnUndo。沿用现有纯迁移投影；不调用会持久化迁移的读取流程，不修复、不补写、不消费恢复点，也不申请阶段生成会话。

先比较调用方与数据库中完整正式状态的规范指纹，防止同 revision 的记忆维护或人物管理变化导致错配。随后验证控制记录必须是当前 journal 的连续后缀；快照头、saveId、turnId、beforeTurnId、字节数、创建身份、turnNumber、前后 revision、完整 journal 前缀和已有 scene 均须吻合。孤立的“较新”快照不会被选中。

撤回会提高并发 revision，而历史 journal 的 revision 保持原样。出现此差值时，只有现有 lastUndo 回执及当前草稿同时证实同一恢复分支，才允许比较。否则安全禁用。原有撤回容量（5 回合／64MiB）、写入事务、锁、撤回及结算函数均未改动。

**保守降级限制：** 若撤回后又执行了会清除 lastUndo 的既有管理操作，比较可能暂时不可用，直到下一次正式结算重新生成可靠恢复点。本轮没有为显示变化而修改该业务行为或新增持久化信息。开局没有结算前恢复点、旧存档没有控制记录、容量跳过、链不连续或损坏时也采用同一降级文案。

## 只读投影与导航

纯函数 `diffTurn(before, after)` 不请求 AI、不修改输入。按照既有玩家资料面板的可见口径投影，排除内部 ID、revision、存档时间戳、重要性标记、休眠人物档案和受保护私密资料。事件与记忆沿用既有资料档案的玩家观察权限，并明确标识客观档案、人物私有、内部记录、转述及推测；不会将后台存在误写为主角知情。

现金和线上余额先转整数 BigInt 分再相减，使用正式 `money()` 输出两位小数。未知余额不视作零。并行事件阶段各自列示；退役阶段沿用事件档案身份，不制造删除后新增。正式史料与纪事分别汇总，不从正文生成记录。

NPC、物品、组织、事件、地点和正式纪事使用已有真实目标 ID。记忆定位既有层级；没有单条定位能力的普通史料、无关联任务、已失去物品提供可用资料入口。地图仅增加可选初始目标适配，并展开目标祖先和已有分段，不提供移动操作。关闭档案柜优先回到变化行；dock 导航清除该来源，避免错误回焦。

为了在收起态显示真实数量与色点，每次可靠状态对仅计算一次差异并缓存；展开、收起及单组展开不重新读库或计算。这是对交接文档“打开时计算一次”的必要适配，既不后台轮询，也不改变正式数据。
