# 游戏主界面「城市长夜」交付说明 · 开局城市绑定修订

设计稿：[heijin-main.html](heijin-main.html)（v5 城市视觉绑定修订），单文件，直接用浏览器打开。
- 「设计稿控制」可以切换示例存档的开局主题、独立的当前地点、时间、天气和回合状态，只用于演示，**不要在游戏中实现控制器**。
- 例如 `#city=cq&place=sh&time=day&wx=snow&flow=busy` 表示重庆开局主题、当前人在上海、白天下雪。`city` 只表示开局主题，`place` 只表示演示的当前位置；历史副标题保留各回合快照。

## 设计修订与正式实施边界

**城市视觉主题以存档开局时确定的城市为准，创建后永久固定，不跟随玩家当前所在地变化。**

本文件保留 v5 已确认的设计与数据绑定要求。UI-2 正式落地按这些要求实施；2026-11-12 用户进一步明确：首个开局回合记录正式 `startAt` 与回合开始前的开场地点，不取结算后的 `endAt` 或移动后地点。实现、验证和截图见 [实施报告](IMPLEMENTATION.md)。

| 元素 | 绑定来源 | 变化规则 |
|---|---|---|
| 背景天际线、城市主题色、环境光的地域色调 | 存档开局城市 | 永久固定；时间只调节明暗、窗灯，不切换城市色相 |
| 所有回合的城市铭牌及其两侧装饰、其他纯城市风格美术 | 同一存档开局城市 | 历史、草稿和预览均用同一主题，不按当前地点或回合地点换皮 |
| 顶栏品牌区城市名、英文名和别称 | 存档开局城市 | 表示本存档视觉身份；与旁边的当前地点区分 |
| 当前日期、星期、时间、昼夜明暗 | 当前 `worldClock` | 随游戏时间变化，GMT+8 |
| 当前天气及天气特效 | 当前 `weatherText` | 随天气变化；城市主题不强制指定天气 |
| 顶部当前地点及面包屑 | 当前 `protagonist.locationId`、`locations` | 随移动变化，包括跨城移动 |
| 每回合副标题中的历史时间、城市和地点 | 该回合的 `journal.scene` | 取本回合发生时的快照，不随之后的移动或时间推进改写；城市文字使用固定主题色 |

不为全国城市补天际线，不实现未来五大地区系统，也不扩展 AI、世界、移动或结算系统。

## 现有数据检查与最小持久化方案

已检查当前仓库，结论如下：

- [`src/ui/creation/model.ts`](../../src/ui/creation/model.ts)：`CreationSchema.city` 是创角时的明确选择；`buildCreationState` 生成标题 `姓名 · 城市名`，并将初始 `protagonist.locationId` 设为城市 id。它只写入 `china → 城市` 两层地点，没有独立保存开局城市。
- [`src/app/App.tsx`](../../src/app/App.tsx)：创角完成后删除 `heijin.creation.v1`；它是全局的单份表单草稿，不是每个存档的永久元数据，不能拿另一份草稿补当前档案。
- [`src/domain/state.ts`](../../src/domain/state.ts)：当前正式存档为 V9，顶层是 `z.strictObject`，没有独立开局城市字段；`protagonist.locationId` 是可变的当前地点。
- [`src/ui/home/skyline.ts`](../../src/ui/home/skyline.ts)：已有 `saveCity(title)` 按标题末尾的 `· 城市名` 识别四城。当前创角自动生成这个后缀，可作为旧档的一次性恢复线索；标题仍是自由文本，不把它作为新档长期身份来源，也不能保证被外部改写过的旧档仍准确。
- 初始地点树的根是 `china`，沿 `parentId` 取根会得到“中国”。当前所在地、唯一城市节点、初始同伴所在地、出生地和正文文字均不能可靠证明开局城市，禁止用来兜底。

**最小增量：只加一个顶层可选字段 `openingCityId: IdSchema.nullable().optional()`。**

- 非空值表示创建存档时确定的城市 id（当前为 `chongqing/shanghai/harbin/guangzhou`）；不强制要求它一直存在于可变的 `locations` 表，也不随地点节点改名、删除或层级调整重算。
- `undefined` 只表示尚未补齐的旧档；`null` 表示已处理但无法可靠恢复，永久使用素版。未知但合法的城市 id 也使用素版，不补美术、不冒充重庆。
- 新建存档时，直接从同一份 `Creation.city` 写入，早于开局生成；新档必须写入该值。不是等首回合 AI 改动地点后再取值。只保留这个身份字段，视觉键 `cq/sh/hrb/gz/other` 在前端映射，不重复存储。
- 旧档：先走现有 V6–V9 读取/迁移与完整校验；缺少字段时，仅按现有 `saveCity(title)` 的四城后缀规则恢复并转换成城市 id，识别不了就写 `null`。有字段（含 `null`）时永远保留，不再读标题或当前地点。无法恢复的旧档照常打开；不声称可以恢复已丢失的真实开局信息。
- 补齐发生在存储边界的一次读写事务内，完整校验通过后才落盘，并在首次展示主题前完成。**同为 V9、但原始记录缺少 `openingCityId` 时也必须写回**：现有 `SaveRepository.load/loadGame` 仅在版本变化时写回，需要补上缺字段条件；不能只在 React 内存里兜底。其他正式读写入口复用同一规范化逻辑。
- 可保持 `schemaVersion: 9`，因为新增字段可选且现有旧档仍能校验；不要把 `null` 设为 Schema 默认值，否则会丢失“未补齐”和“已确定未知”的区别。保留已有 V6–V8 迁移支持与损坏存档保护，不能为补字段绕开校验。
- 定位、改标题、结算、重新 Roll、切换存档和刷新都不得修改已固定的值。旧撤回快照可能缺字段：恢复时以当前正式存档已固定的 `openingCityId`（含 `null`）为准覆盖快照候选，再校验和保存；不可从旧快照的标题或所在地重新决定主题。新的快照自然携带字段。
- 兼容目标是**旧存档可在新程序打开**。由于顶层为 strictObject，携带新字段的存档可能被旧程序拒绝；不要求降级兼容，不为旧程序剥离字段。

UI-2 按此方案实现；AI 输出格式、提示词、命令协议和游戏 revision 均不因视觉身份补齐而改变。

## 核心：氛围层（城市底色 + 时间光 + 天气）
做法是新增一个 `<div class="atmo" aria-hidden>`，固定在最底层；所有面板改成半透明玻璃（`backdrop-filter: blur(18px)`），让城市从面板后面透出来。

氛围层由一个固定身份和两个动态状态组成；`data-city` 只读已经固定并持久化的开局身份，不能直接由 `protagonist.locationId` 的当前值决定：

| 变量 | 来源 | 规则 |
|---|---|---|
| `data-city` | 已固定的 `openingCityId` | `chongqing→cq`、`shanghai→sh`、`harbin→hrb`、`guangzhou→gz`；其他 id 或 `null` 统一为 `other`，沿用现有中性回退色 `#7FA7A0`、无天际线、素版铭牌和渐隐金线；不改写开局 id |
| `data-time` | `worldClock` 按 GMT+8 取小时 | 5–7 dawn（黎明）、7–17 day（午后/白天）、17–19 dusk（黄昏）、19–23 night（入夜）、23–5 late（深夜）；`openingTimePending` 时用 night |
| `data-wx` | `weatherText` 关键词 | 含「雨」→rain、「雪」→snow、「雾/霾」→fog、「阴/云」→cloud，其余→clear；同时匹配多个时按此顺序取第一个 |

- **天际线：** 复用 `src/ui/home/skyline.ts` 已有四城几何和种子，城市选择与种子绑定开局身份。夜间窗灯亮度由 `--lights` 控制，白天几乎不亮。抽取时不要夹带首页哈尔滨 SVG 内置的雪花：主界面的雪只由当前天气控制。
- **四城色值：** 与首页一致——重庆 `#7FA7A0`、上海 `#8E9BD8`、哈尔滨 `#A9C3D8`、广州 `#D08A6A`。
- **推导函数：** 建议写成纯函数 `deriveAtmosphere(state) → {city, time, weather}`：`city` 只映射 `openingCityId`；`time/weather` 读取当前字段。不在此函数迁移、写存档或沿当前地点查主题。地点层级查找只供当前地点和历史场景文字使用，遇到国家节点、未知节点或环时安全结束。
- **reduced-motion：** 关掉雨、雪、雾的动画，以及列车和窗灯闪烁，只保留静态色调。

## 各区域
**顶栏（76px，横跨左栏和中栏）**
- 左段：品牌印章、开局城市名（衬线）、英文名和别称，跟随固定视觉身份；未知身份显示中性「城市长夜」，不借用当前城市。设计稿「其他城市」用杭州示例，使用素版美术。
- 中段：
  - 地点：面包屑小字，地点名用大号衬线；只读当前地点，跨城移动后及时变化，与左段开局城市可不同。
  - 时钟：大号等宽 `HH:MM`，旁边是当前日期、星期和时段词（深夜/黄昏…），全部随 `worldClock` 更新，时段词跟 `data-time` 走。
- 右段：天气、环境**分两行**，各自截断，`title` 放全文。天气小印章的字跟随 `data-wx`（雨/雪/雾/阴/晴）。

**左栏（主角卷宗）**
- 内容按顺序：
  1. 印章头像、姓名、年龄·性别·职业
  2. 资金：现金为金色，线上资金
  3. 状态：身体、情绪，左边框用城市色
  4. 当前穿戴与装备：7 行，数据已在 `GameScreen` 里算好，传进来即可；值为「无」的行变暗
  5. 底部按钮：「人物档案」「经济与资产」
- 矮屏（≤860px 高）时压缩间距；左栏自身可以滚动。

**中栏（剧情）**
- 阅读宽度上限 `--read: 1120px`，左右留白至少 28px；稿纸内边距 `clamp(1.4rem, 2.6vw, 2.6rem)`。左栏 `clamp(232px,17vw,280px)`，dock 76px（901–1199px 时为 220px / 68px）。输入台与阅读区同宽。顶部用 mask 淡出，不要用 sticky 遮罩。
- 稿纸实测宽度：1920 → 1120、1440 → 1063、1280 → 916、1100 → 756（px）。
- 每回合是一张玻璃「稿纸」：四角金色折角，回合标题居中，两侧加金线。
- 历史回合透明度 0.62，悬停恢复。
- **回合标题**采用「居中城市回目」，去掉原来的红色装饰印：
  - 布局：一行三列，依次是左侧线、中间城市铭牌、右侧线；第二行居中显示副标题。
  - 铭牌按开局身份对应的 `data-city` 选型，创建后永久固定，所有回合一致：
    - 重庆：轻轨站牌，圆形线路号加站点连线。
    - 上海：深蓝搪瓷门牌「12号」，带铆钉。
    - 哈尔滨：冰刻拱牌。
    - 广州：霓虹招牌，用大写数字写成「第拾贰回」，偶尔闪烁。
  - 两侧线也按固定开局主题选型：重庆是带站点圆的轨道线，上海是双细线，哈尔滨是霜线，广州是发光灯管。
  - 开局身份未知或没有对应美术时，使用居中素版（设计稿里选「其他城市」可预览，`data-city="other"`）：金色「第 十 二 回」加渐隐金线，不显示天际线。当前地点或历史场景推导不出城市，不会改变铭牌。
  - 副标题格式：`十一月十日 · 星期二 · 二十三时四十一分 · 重庆 · 地点名`。日期、星期和时间都用中文数字，星期日写「星期日」，星期按该回合 `scene.worldClock` 的日期在 GMT+8 下计算；城市名用固定主题色；整点写成「二十时整」。
  - 状态：已结算不显示；草稿和预览时在副标题末尾追加「· 草稿」或「· 预览」；草稿时铭牌变灰。
  - `<h2>` 的文本保持「第 N 回合」不变（读屏和现有测试依赖它）。铭牌和副标题都标 `aria-hidden`。
  - 中文数字函数 `cn()`、大写函数 `dx()`、副标题函数 `cnTime()` 都在设计稿脚本里，可以直接搬，支持到 999 回合。
  - **副标题数据（已定：每回合都显示，需在存档里记录）：**
    - `src/domain/state.ts` 的 journal 条目（`z.strictObject`）新增**可选**字段：
      `scene: z.strictObject({ worldClock: GameTimeSchema, locationId: IdSchema }).optional()`
      其中时间 schema 沿用 `worldClock` 现有的那个。
    - 写入时机在 `src/domain/turnCommit.ts` 追加 journal 那一步：
      - 记录**本回合开始时**的场景，也就是 `current.worldClock` 和 `current.protagonist.locationId`。副标题描述的是「这一幕发生在何时何地」。
      - 例外是开局回合（`current.openingTimePending` 为真）：时间取本次正式结算已经验证的 `openingTimeSelection(current, draft).startAt`；地点仍取 `current.protagonist.locationId`，这是开局生成前的正式起点。创角只有城市节点时记录城市，不猜测本幕结束后的精确地点。
    - 渲染时只用该条 `scene.locationId` 查 `state.locations` 得到历史地点名，再沿 `parentId` 找到城市层（不能误取 `china`）。这里解析的城市只显示为副标题文字，绝不用于选择铭牌或装饰。它记录的是发生时的地点引用，不是地点名称快照。
      - 地点已被删除或查不到时，副标题只显示「日期 · 星期 · 时间」。
      - 推导不出历史城市但地点仍存在时，保留日期时间与地点名，省略城市文字；铭牌仍用固定开局主题。
    - 旧存档里没有 `scene` 的回合：副标题显示暗色的「时间地点未记录」，铭牌照常，每回合的版式保持一致。
    - 兼容性：
      - `scene` 是可选的，不为旧回合编造时间地点，也不因该字段调整 schemaVersion；开局身份字段另按上文做一次性持久化补齐。
      - 但 journal 是 strictObject，**新版写出的存档在旧版程序里会校验失败**（不能降级）。请在 PR 里写明。
      - 撤回回合时 journal 条目整条移除，`scene` 跟着一起删掉，无需额外处理。
    - 补测试：
      - 有 `scene` 和没有 `scene` 的存档都能通过 `GameStateSchema`。
      - 结算后最新条目带正确的开始时间和地点；开局回合用正式 `startAt` 与开场地点，且正式世界时钟仍按原逻辑保存 `endAt`。
      - 撤回后 `scene` 一并消失。
    - AI 输出格式、提示词、三阶段与结算的其他逻辑都不改。
- 正文用衬线，行高 2.05。
- 对白采用「剧本台词」样式，不再用气泡：
  - 用三列 grid：小圆头像（`.story-avatar`，1.6rem）｜说话人名字（4.4rem，衬线、字距 .2em，过长省略）｜台词。`.story-speech` 设为 `display: contents`，让名字和台词直接进入 grid。
  - 台词前后用 CSS 伪元素加「」，左侧 1px 细线，无边框、无底色。
  - 主角：名字和头像为金色，左线 2px 金色，台词文字偏暖白，再加一层很淡的金色横向渐变底。
  - `StoryReading.tsx` 的 DOM 结构不变，只改样式。用 grid 把 `.story-avatar` 和 `.story-speaker` 放进左栏，`.story-bubble` 放进右栏。
  - 多行台词要保持悬挂缩进。
- 预览/草稿标签放在标题下方居中，正在流式输出的正文末尾显示闪烁光标。
- 行动建议：
  - 两列卡片，数量为奇数时最后一张通栏。
  - 序号徽标 `01`，左侧金条在悬停或选中时出现。
  - 点击后填入输入框（现有行为）；数字键 1–5 也可以选中对应卡片（新增快捷键，焦点不在输入框时才生效）。

## 验收要点
1. 在 1920×1080、1440×900、1280×800、1100×800 下，页面无横向溢出；顶栏各段互不重叠，长文本只截断，`title` 有全文。
2. 四城 × 五时段 × 五天气任意组合下，正文对比度达到 WCAG AA（稿纸底与文字 ≥ 4.5:1）。白天模式尤其要检查。
3. 重庆开局后移动到上海，顶栏当前地点显示上海，但天际线、地域色调、所有回合铭牌与装饰仍为重庆；切换其他存档再返回、刷新重载、改标题和撤回都保持一致。测试必须覆盖当前地点存在/缺失、跨城、国家根节点，以及历史 scene 城市与开局城市不同。
4. 修改 `weatherText`、`worldClock` 后，天气、当前日期/星期/时间与昼夜明暗即时更新，城市身份不变；历史副标题不被覆盖。旧回合缺 `scene` 时只显示「时间地点未记录」，不能影响铭牌。为后续实现的 `deriveAtmosphere` 覆盖四城、未知/无美术城市、时段边界（5/7/17/19/23 点）、天气优先级及 reduced-motion；存储测试覆盖 V6–V9 旧档、同版缺字段写回、标题线索恢复、未知身份写 `null` 后重载保持、撤回旧快照保留身份，以及补齐失败不覆盖原档。既有 e2e 保留行为断言；与本绑定修订相关的新增断言按新规则。
5. reduced-motion 下无动画。氛围层不可聚焦，读屏器不朗读。
6. 性能：天气只用 CSS 背景动画，不用 canvas 或逐帧 JS；在 1440 宽的普通笔记本上滚动正文不掉帧。
