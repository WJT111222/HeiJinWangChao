# 王朝小剧场 V1

## 玩家操作

桌面从右侧资料坞打开「小剧场」，手机从「世界资料」进入。每份存档有独立列表，支持新建、阅读、复制全文、重命名、续写、重新 Roll、更换模型和删除。列表一次读取 20 条索引。长篇正文分段挂载，段内沿用主线阅读排版，全文复制包含全部段落。

新建时填写主题，可以自行命名或由主题生成标题。篇幅有 1500、3000、5000、10000 字四档，自定义范围为 100～100000 字。可以跟随主线人称，也可以为每篇指定第一、第二或第三人称。流式默认沿用当时的正文设置，可以单独切换。篇幅是提示词中的创作目标。实际输出上限取所选渠道的配置。

「设置 → 提示词管理」可以查看、编辑并恢复小剧场提示词，保存后适用于新建作品。已建作品保留创建时的提示词和其他配置。

## 生成和隔离

- 正式入口读取 IndexedDB 中最新已结算的 GameState。背景由公开人物资料、地点、天气、环境、近况、公共记忆及相关组织和已知事件组成。主线回合、版本和时间随实际发送的背景一起冻结。首次开局时间未确认时，冻结时间为空。
- 背景最多 36,000 个 UTF-16 码元，并受约 8,000 估算 Token 的限制。单次输入最多约 16,000 估算 Token。续写优先保留故事开头和最近正文，最多选取约 8,200 个码元，并在序列化后按预算缩减。请求会标记前文省略。两次正文之间只去除可确定的边界重复，已保存的前文保持原样。
- 小剧场直接使用现有 AiClient、凭证库及四协议请求转换。默认选择当时的正文模型，也可单独指定渠道和模型 ID。每篇记录渠道、模型、协议、地址摘要、采样及输出上限的期望配置、流式、叙事方式和超时。启动时重新从凭证库读取密钥。渠道被移除、地址或协议改变、服务返回模型不可用时，可手动更换模型。小剧场使用渠道直连，浏览器仍须能访问所选端点。
- 新建、续写和重新 Roll 各发起一次 POST。浏览、复制、重命名和删除为零 POST。同篇通过 Web Locks 排除跨标签重复生成，通过存档实例和小剧场修订号拒绝迟到写入。浏览器缺少 Web Locks 时，生成会提示并安全退出。
- 正文与公开思考分开。结束标记、输出上限、取消、超时及读流中断分别处理。有效片段可由玩家选择保留，重新 Roll 的未完成结果可另存为独立小剧场。完整的新正文经事务保存后才替换原文，存储失败保留原文。
- 小剧场请求使用独立提示词与背景容器。三阶段、主线记忆、正式草稿和世界状态只在原有流程中写入。自动重试、自动续写、酒馆脚本、文学预设和原生防截断均不在小剧场路径上。

## 存储、备份与恢复

| 情况 | 行为 |
| --- | --- |
| 浏览器数据库升级 | IndexedDB V6 新增 theaterIndex 和 theaterBodies。GameState、TurnDraft、历史节点和源记忆沿用原有结构。 |
| 单篇保存 | 正文和索引同事务写入，每篇保存一个正式版本。单篇正文上限为 1,000,000 个 UTF-16 码元，列表没有篇数上限。 |
| 普通备份和导出全部 | V2 文件为每份存档明确保存小剧场集合，空集合也写入。延续现有 256 MiB 文件上限。超限拒绝导出，原数据可继续读取。 |
| V2 同 ID 导入 | 确认界面显示小剧场差异。确认后原子覆盖该存档的小剧场集合，期间新增或修改作品会使旧确认失效。 |
| 同名不同 ID | 各自独立。导入、删除和确认按实际存档 ID 归属。 |
| V1 旧备份 | 正常读入。覆盖同一存档且创建时间一致时保留本机小剧场。已有小剧场而归属无法核对时拒绝覆盖。 |
| 历史收藏与撤回 | 主线回溯、撤回和节点收藏保留独立小剧场。历史节点单独导出沿用只含主线的 V1 格式。 |
| 删除存档 | 可读存档的正式删除事务同步清理相关小剧场。损坏存档还有关联小剧场时，原始数据导出不包含小剧场，因此拒绝删除。 |
| 存储与凭证 | 浏览器配额或事务失败保留已有数据。记录只含生成配置、准备过的背景和小说正文。没有鉴权头、API 密钥或供应商公开思考。 |

旧版程序需升级后才能导入含小剧场的 V2 普通备份。现有存档馆备份状态仍按主线版本计算，小剧场修改后需要重新导出才能让文件包含最新正文。

## 验收范围

- 工程检查采用 Node 24 和现有锁文件。提示词 Manifest 和来源锁由仓库脚本更新。
- Vitest 覆盖四协议的 JSON 和 SSE、冻结的模型和输入、部分响应、超时、断流、意外工具、模型失效、凭证隔离、续写去重及保留旧文。存储测试覆盖列表分页、备份和历史恢复、多个存档、撤回、容量保护、过期确认和删除后的迟到响应。
- Chromium 在桌面与手机分别验证长文读写、内部滚动、复制、停止实际响应、跨标签生成锁及设置保存。检查小剧场操作前后的正式状态与草稿，随后捕获一条主线请求，检查正文和主题未进入主线上下文。
- 模型传输使用本地合成响应。真实供应商、真实移动设备和不同服务的实际上下文窗口仍待验证。

本轮本地记录使用 Node 24.19.0、Chromium 154 和项目锁文件。Vitest 共 5,310 项，通过提示词专项 93 项。新增 Chromium 场景 6 项全部通过。包含小剧场、普通备份、历史收藏、连续主线和跨标签设置的定向批次为 20 通过、4 项按原套件的平台限制跳过。该批次的长篇夹具超过两万字符，最终小剧场专项另验了跨段阅读和全文复制。
