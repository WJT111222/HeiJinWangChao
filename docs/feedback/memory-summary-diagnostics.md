基线为 `d65f4a8bc81608a3cf352f57ad5595bfc98d0c98`。范围涵盖短期到中期、中期到长期、NPC 短期到中期三类任务。

## 如何查看

记忆失败弹窗和设置中的失败状态均有「查看总结诊断与模型原文」。在「模型原文」中也可按请求查看近期总结，复制原文或安全诊断。原文与供应商独立公开思考分开。页面临时缓存沿用最近六次请求及现有容量上限，刷新、清除或淘汰后，失败记录仍可显示结构化诊断。持久记录只附加安全元数据，原文和公开思考不写入账本或存档。

## 失败位置

准备、请求、输出校验、保存各自记录实际失败原因。JSON 和 Schema 诊断来自现有校验的失败位置，只展示允许的字段路径。NPC 诊断可以同时显示预期与实收分组数量，省略实际分组 ID。未解决事项、矛盾、分组缺失、重复、不匹配和容量超限仍触发原有拒绝规则，错误仍保留原有代码。报出的输出长度是捕获的内容 UTF-16 代码单元数，只有收到明确的输出上限信号才标记模型截断。临时展示容量另有独立提示。

总结请求继续按原协议发送非流式请求。若供应商意外返回 SSE，观察器会尝试保留已经收到并能提取的公开响应字段。该观察结果只用于诊断，即使 SSE 正常结束也不会保存为总结。正确的 JSON 即使媒体类型被误标仍按旧路径接收。未能提取结构化内容的响应不会被补写或重新请求。

## 实际上报字段

[Chromium 拦截到的三份脱敏请求](evidence/memory-summary-requests.json)来自同一次合成测试。外层沿用 `submissionId` 和 `feedback`，文件保留请求中的 `feedback` 对象，省略提交回执关联用的随机 UUID。

- `feedback.errors[]` 使用 `stage: "memory"`，并保留日志编号、时间、错误码。可用时补充模型、协议及 HTTP 状态。
- `memory` 包含任务、步骤、原因、错误码、请求时间、构建标识，以及实际可用的字段路径、分组数量、输出长度和截断信号。
- 两项附件默认关闭。选择原文或公开思考时只发送对应字段，使用报告内 `errorRef` 关联。原文清除后仍可提交日志。
- 后台可组合失败阶段、记忆任务、模型与错误码筛选。筛选条件匹配同一条日志。邮件仅聚合白名单内的阶段、任务、原因及代码等元数据。

D1 沿用现有 JSON 列，旧反馈直接读取。本轮无数据库迁移。账本沿用原有互斥和原批授权。持有旧版应用的标签页如果遇到新版严格账本字段，会按既有保护停止请求，刷新到新版后可继续操作。
